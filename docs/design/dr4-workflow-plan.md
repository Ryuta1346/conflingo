## 着手時の現状

1. `ConferenceKnowledgeView`に保存・書き出し・資料管理・認識方式・用語・発話質問・資料だけの質問・補正が同居する。LLM設定もここから開く。
2. DR2で発話質問の下書きは`workspace.assistanceDraft`へ集約済み。資料だけの質問はシート内の`@State`であり、分割時に消失させない。
3. MeetingとConferenceでAI許可の文言と配置が異なる。Web調査、資料だけの質問、補正、要約は独立した許可・確認経路を持つ。
4. Appのメニュー追加は小窓表示のみ。設定Sceneがなく、拡大縮小のショートカットは画面ボタンに付いている。
5. Meeting準備は会議名の常設ラベルがなく、未選択入力の言語・権限も表示する。認識言語は日本語と英語の固定2択。開始不可理由の表示がない。
6. `AssistanceAnswerView`の回答・引用発話は文字サイズ設定を受け取らず、資料引用シートは16pt固定。

## 1. Conferenceの導線を分ける（D08）

- 準備画面に「資料・用語・認識方式」を配置する。現在の取込・ライブラリ選択・用語抽出・用語適用を維持し、状態に応じた編集可否を引き継ぐ。
- 実行中の「資料」ボタンからは資料追加・選択・用語だけのシートを開く。実行中の追加という既存機能を残し、認識方式は停止後の準備で変更する。
- 発話＋資料への質問と提案は、DR2で作った開閉可能なAI支援欄へ集約する。狭幅オーバーレイ・広幅サイド欄の境界と入力状態を維持する。
- 「資料だけに質問」はAI支援欄の質問対象切替（「発話と資料」「資料のみ」）へ移す。既存の資料専用要求・独立した許可をそのまま使い、対象を切り替えても両方の下書きと完成回答を保持する。資料のみの要求に発話を追加しない。開始前も準備画面からAI支援欄を開けるようにする。
- 補正は確定字幕行の「資料で補正」から、その発話を選択した専用シートを開く。キーボードで到達可能な操作とし、原文保持・候補比較・採用／取消・保存／Markdownへの反映を維持する。
- 資料シートから保存・書き出しを除き、既存の上部操作へ統一する。準備中の資料質問の完成回答も、既存の保存条件を満たす場合は上部から保存可能にする。
- LLM接続管理は共通の設定へ案内する。資料シート→LLM設定→接続編集という重なりを解消する。移動・開閉で収集中の音声や下書きを失わない。

## 2. 共通の送信範囲パネル（D10）

「用途／送る内容／送信先／実行時点／許可状態」を共通表示する。狭幅では項目ごとに縦へ折り返す。

| 用途 | 内容と契約 | 表示場所 |
|---|---|---|
| 発話への手動質問 | 質問＋直近の確定発話最大30件。資料参照は別許可 | 両モードのAI設定 |
| 自動提案 | 既存の発話範囲・回数制御を維持。資料参照は別許可 | 両モードのAI設定 |
| 資料だけの質問 | 質問＋資料の抜粋最大5箇所・6,000文字。発話なし | ConferenceのAI設定 |
| Web調査 | 既存の発話・資料範囲と独立許可。検索サービスへの文脈利用を明記 | 共通パネルから既存の調査確認へ |
| 終了後要約 | 会議全体の分割送信計画と資料選択を維持 | Meetingの要約確認へ |
| 字幕補正 | 選択発話・通常訳・関連資料・適用用語 | Conferenceの補正確認へ |

- 選択接続の名前・送信先URL、音声を送らないこと、料金・データ保持条件を明示する。用途ごとに異なる上限を一律の「30件」に置き換えない。
- 発話送信→自動提案→自動提案の資料、という親子関係を字下げと無効理由で示す。資料だけの質問・Web調査・補正の独立性を保つ。
- 共通化するのは表示とバインディング。既存の状態所有元・取消・許可撤回・世代判定・初期値を維持し、共通パネル表示によって許可を付与しない。
- 要約・Web調査・補正の実行直前の確認を残す。未提供の用途を実行可能に見せない。

## 3. Macのメニュー・キーボード操作（D11）

- 共通の設定内容を利用するSettingsシーンを設け、アプリメニューと⌘,から開く。設定を開くだけで音声収集を止めない。配色・文字サイズ・最前面・LLM選択は既存の状態を共有する。
- 「セッション」メニューに現在のモードの開始／停止または一時停止／再開（⌘R）、Meeting終了（⌘⇧E）、小窓表示を用意する。終了は既存の確認を経由する。
- 「表示」メニューに文字を拡大／縮小と最前面を設ける。拡大はUS配列の⌘=と⌘⇧=（⌘+）、縮小は⌘−を確認し、1回の入力で2段階変わらないよう重複登録を避ける。JIS配列での実確認可否は結果に記す。
- メイン窓／小窓の対象と状態に応じて有効化し、設定窓や編集シートでセッション操作を誤発火させない。開始・停止・保存中のガードを既存のボタンと共有する。
- 編集シートの確定操作にReturn、取消・閲覧シートの閉じる操作にEscapeを設定する。複数行入力・日本語変換中はReturnで送信／確定しない。削除・会議終了を無条件のデフォルト操作にしない。

## 4. Meeting準備フォーム（D12）

- 会議名を常設ラベル付きにする。Conferenceと同じラベル上置きのフォーム配置を用い、狭幅では1列へ折り返す。
- 入力選択に含まれる入力だけ、認識言語・翻訳先・権限状態を表示する。非表示側の選択値は保持し、切替で勝手に初期化しない。
- 認識言語は既存の`ModelPreparing.sourceLocales()`を使い、Conferenceと同じOS対応一覧を表示する。読込中・空・保存済み値が一覧にない状態を扱い、未対応値を対応済みと表示しない。
- 開始不可理由を開始操作の近くに表示する。同意未確認・処理中・資料処理中等を既存の`canStart`と一致させる。
- 選択入力の権限を記号と文で示し、拒否時に該当するシステム設定への操作を出す。権限未確認は拒否と区別し、従来どおり開始時の確認を可能にする。
- 音声・翻訳モデルの準備、入力3構成、同意、開始／取消／再開の契約を維持する。

## 5. 文字サイズは読む本文へ適用（D13）

- 設定名を「読む文字のサイズ」にし、対象を字幕・AI回答・引用・資料本文・要約・履歴本文と説明する。既存の10〜48pt・2pt刻み・保存キーを維持する。
- 共通回答、Web調査、根拠発話、資料引用へ設定値を渡し、Meeting／Conference／履歴／小窓で一貫させる。生成途中の本文も対象とする。
- 一覧の題名、出典リンクのラベル、日時、フォーム、ボタン、送信範囲の説明はDR3の文字様式を使う。補助12pt以上・送信説明14ptの契約は維持する。
- 16／32／48ptで長文・日本語・URLを確認し、操作が画面外へ押し出された場合もスクロールとキーボードで到達できるようにする。
