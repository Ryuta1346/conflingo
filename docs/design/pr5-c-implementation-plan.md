## 今回の範囲

| 領域 | 実装する動作 |
|---|---|
| App Shell / Home | Meetingへの入口。ConferenceとMeetingを同時に開始しない。現在の会議へ戻れる |
| Preparation | 会議名、マイク/内部音声の入力別認識言語、通知・同意の確認、権限/準備状況、開始/準備取消/再試行 |
| Live | 入力元・時刻・途中/確定を持つ会話表示、読み返し/最新へ、一時停止/再開/終了、入力エラーと停止再試行 |
| Insight / 根拠 | 提案・種類・未確認表示・発話IDに基づく時刻/引用への移動。架空提案はDEBUGプレビューだけに供給する |
| Review | 終了後の会議名・入力言語・確定発話・取得済み提案の表示、保持したまま戻る/確認して破棄。候補がある場合は未確認と表示 |
| Floating | 重要提案最大1件、入力別状態、AI状態、停止操作。コンパクト/展開/非表示/再表示。位置・サイズの保存と画面内への復帰 |
| 検証用プレビュー | 非録音のfake入力・固定イベントで正常/失敗/AI送信中/オフライン/候補あり等を再現。通常起動とReleaseでは有効にしない |

通常起動ではMeetingのローカル文字起こしを提供し、AI未接続を明示する。架空の回答・擬似的な送信成功を表示しない。送信先が未確定のため、通常UIに機能しないAI許可スイッチ・Ask AIボタンは設けず、PR6接続時に追加する。音声の取得と録音ファイルへの保存を言葉でも区別する。

PR6のLLM/ネットワーク/手動質問の実処理、PR7の候補確認・却下/要約/Meeting Markdown書き出し、Sessions永続化、PR8の資料取り込み/検索は今回含めない。Reviewは「アプリ終了まで保持・未保存」と説明し、未実装の保存操作を成功したように見せない。既存Conferenceの書き出し機能は維持する。

## コードから確認した制約と設計

1. `DualTranscriptionController`は`MeetingSessionStore`を所有する。`stop()`は最後のfinalを取り込み、partialを消去した後にidleへ戻る。`clear()`だけが会議ID/時刻/発話をリセットする。一時停止は`stop()`、再開は同じcontrollerの`start()`とし、間に`clear()`しない。時刻は休止時間も含む既存共通Timelineを維持する。
2. 低レベルのphaseはidle/preparing/listening/stoppingのみ。準備画面・一時停止・ReviewというUI上の意図は最小のMeeting状態として保持し、入力状態を二重管理しない。自然な入力失敗でidleになった場合を、ユーザーによる会議終了と取り違えない。
3. 停止失敗ではcontrollerがstoppingに留まる。UIで実行中と再試行可能を区別するため、既存stopTaskの有無から導く読取専用`isStopping`を必要に応じて追加する。phaseやエラー文字列から偽の成功を作らない。
4. `ConfLingoApp`は共通`AudioInputUse`と2入力検証用controllerを保持する。Meeting用controllerは検証用とは別に1つだけ作成し、主画面と小窓で共有する。共通排他管理を使い、所有者にMeetingを追加する。既存検証用controllerの既定値は維持する。
5. `ContentView`はConferenceのstore/controller、モデル準備、translationTaskの所有者。Meetingへの画面切替でこの所有者を破棄しない。App Shellのナビゲーションを拡張し、現在のConference停止確認を維持する。Meeting側の停止・遷移判断はMeetingの状態を参照する。
6. `MeetingSessionStore`の発話を別配列へ複製して状態管理しない。提案はPR6の通信仕様を先取りせず、表示に必要なID/種別/本文/重要度/根拠発話IDだけを持つ値として扱う。存在しない根拠IDは「参照できません」と表示する。
7. Floatingの表示状態は収集状態と独立。自動更新でアプリを前面化しない。実装時にSwiftUI/AppKitの利用APIを公式資料で確認し、必要なウィンドウ制御に限定する。共有画面に映らないという保証はしない。

## 操作契約

- 新規会議開始前に通知・同意の確認が必要。チェックを相手への通知送信や法的同意取得の代行とは扱わない。新規会議で確認をリセットする。AIへの送信許可とは分ける。
- 日本語/英語を入力ごとに選べる。準備失敗は実際のモデル/権限結果に従い表示する。入力取得が始まっていない状態を「取得中」と表示しない。
- preparing中は設定変更と二重開始を抑止。取消は既存`stop()`で準備中タスクの終了を待つ。遅れて返る結果で画面や入力を再開しない。
- Pauseは両入力停止完了を待ってpausedへ進む。再開は同じ会議ID/発話/設定を保持する。終了は停止とfinal取り込み完了後だけReviewへ進む。
- 停止失敗なら現在画面と発話を保持し、再試行可能にする。新規開始・破棄・成功扱いの遷移は禁止する。
- 別モード/設定への移動は、収集中なら確認して停止する。停止後も会議を保持し、Meetingへ戻れば再開できる。準備/停止処理中は別モードへ遷移しない。
- メインウィンドウの通常の閉鎖は停止確認を行い、停止成功後だけ閉じる。Floatingの閉じる操作は非表示として扱い、収集は継続する。ウィンドウメニューから再表示できる。アプリ終了時にはセッションを永続化しない。新しいCmd+Q終了ガードは今回の範囲に含めない。
- 読み返し中は新しい発話でスクロールを奪わない。「最新へ」で追従を再開する。リサイズ・小窓への切替/復帰で発話と読み返し状態を保持する。根拠への移動は利用者の明示操作に限定する。
- 小窓の非表示・再表示・リサイズで音声サービスや会議storeを生成し直さない。表示更新でフォーカスを奪わない。モニター構成が変わっても保存位置から画面内へ戻せる。
- Reviewから新規会議へ移る/破棄する際は、未保存の発話がある場合に確認する。取消で保持し、確定後だけ`clear()`する。ナビゲーションや窓の非表示では消去しない。
