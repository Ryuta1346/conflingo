## 目的と受入条件

640pt幅・520pt高のコンテンツ領域で、文字サイズ16pt/48ptの両方において次の操作がキーボードだけで完結し、操作対象が見えること。1180pt幅でも回帰がないこと。

| ID | 観測した問題 | 合格条件 |
|---|---|---|
| U01 | Sessions詳細で根拠へ移動すると上部操作が画面外になり、Tabでも一覧へ戻れない | 根拠の発話が表示され、その後Tab/Shift+Tabで「一覧へ」「Markdownを書き出す」「削除」に到達できる。対象は画面内に表示され、「一覧へ」を実行できる |
| U02 | 資料詳細の文書選択から本文にフォーカスできず、Page Downで本文を読み進められない | Tabで本文スクロール領域へ到達し、Page Down/Upで本文の表示範囲が変わる。先頭と末尾へ到達でき、Shift+Tabで文書選択へ戻れる。文書切替後も本文が読み進められる |
| U03 | 設定画面でTabにより画面外のコントロールへ移動してもスクロールが追従しない | Tab/Shift+TabでAI回答言語・接続先・接続追加・編集などへ移動すると、対象とフォーカス表示が可視範囲に入る。編集シートの取消後も戻り先が見える |

## 修正方針と対象

1. `ConfLingo/Sessions/SavedSessionView.swift`
   - 上部操作行を本文のLazyVStack/ScrollViewから外し、スクロール後も残る位置に配置する。
   - 根拠へのスクロールと長い履歴の遅延表示を保持する。
   - 640pt幅で3操作が収まることを確認する。
2. `ConfLingo/KnowledgeLibrary/KnowledgeLibraryView.swift`
   - 本文のスクロール領域へキーボードフォーカスを与え、フォーカス位置を視認可能にする。
   - 本文にフォーカスがある場合のページ移動・先頭末尾への移動を扱う。文書一覧の操作や本文の選択・コピーを妨げない。
   - まずSwiftUIの公開フォーカス/キー操作APIで実現し、必要な場合だけ当該領域に限定したAppKit連携を追加する。
3. `ConfLingo/App/SettingsView.swift` / `ConfLingo/Meeting/Views/LLMSettingsView.swift`
   - コントロールのフォーカスにスクロール位置を追従させる。
   - 親の設定ページと内側のLLM操作を接続し、逆順移動とシート取消後も扱う。
   - 公開APIと局所的な変更を優先し、グローバルなキー監視・メソッド差替えは導入しない。

調査で確認した構造は原因候補であり、修正効果は失敗テストと実画面で検証する。保存形式、通信処理、接続設定の意味は変更対象に含めない。
