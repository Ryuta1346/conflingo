# ConfLingo — フロー・状態・受入仕様 v0.1

2026-11-08 / PR5-A モックの方向性承認済み。以下の個別受入項目はユーザーによる実施・合格を記録するものではなく、未検証を維持。モック上部のレビュー操作は製品UIの外側。画面切替は任意状態へのジャンプ、画面内の開始/停止は連続フローの試作。

## 主要フロー

1. **Conference:** Home→準備（言語、開始モード（既定は文字起こし）、高速確定、辞書）→開始→字幕→停止→再開またはMarkdown書き出し。Clearは停止後に確認して消去。辞書編集は準備へ戻る。
2. **Meeting:** Home→会議名・入力別言語→参加者への通知/同意確認→クラウドAIの任意許可→開始→Live。音声は保存/送信せず、AI許可時のみ必要な確定発話等を送る設計。通知チェックは相手の同意取得そのものを代行しない。
3. **提案と根拠:** 提案→発話時刻→引用→戻る。決定/アクションは「候補」から明示的に確認/却下。生成だけで確定しない。
4. **中断:** 収集を一時停止→新しい収集/AI送信を停止→再開。クラウドAI停止は音声収集を止めない。会議終了は両方停止し、残ったfinal処理完了後Reviewへ。停止失敗ならReviewへ遷移しない。
5. **振り返り:** PR7ではReviewで候補確認→任意の手動AI要約→Markdown書き出し。アプリ内への明示的ローカル保存は後続。保存しない場合は確認して破棄。書き出しとアプリ内保存は別操作。
6. **Sessions（後続）:** 明示保存された会議だけを検索/閲覧/削除。削除は確認後実施。書き出した外部Markdownは連動削除しない。
7. **Floating:** Live→コンパクト→展開復帰。非表示は収集停止ではない。復帰はアプリのウィンドウメニュー等から。モックはOS操作を代替する「再表示」ボタンを外側に置く。

入力切断時に片方だけ継続する設計にはしない。PR4は片系失敗で両系統を停止する。AIネットワーク障害は音声とは独立して縮退する。

PR6のヒアリング反映（実装・モック検証済み、実API受入待ち）: Geminiへの直接接続と利用者のAPIキーを使う。会議ごとのAI送信許可と自動提案スイッチは別々で、どちらも初期オフ。送信許可後は手動Ask AIが基本となり、自動提案は別途オンにした場合だけ動く。設定のキー登録/置換/削除はKeychainへ反映し、失敗を成功表示しない。料金・提供者のデータ利用条件を説明し、キーだけから無料/有料区分やゼロ保持を断定しない。通信失敗後の再送は明示操作に限る。PR6でこれらの操作を追加した。[検証記録](../validation/pr6-insights.md)[PR6計画](pr6-implementation-plan.md)
