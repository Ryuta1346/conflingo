# PR5-A UI/UX設計 作業計画

2026-11-08 / 設計着手はユーザー「PR5-Aをすすめる」により承認済み。主要4画面の画像提示後、ユーザー「OK」によりモックの方向性を承認（2026-11-08）。各状態の実機受入・後続の実装計画承認とは別。

## 範囲と順序

1. 現行SwiftUIを監査し、既存機能の移設表・画面構成・状態と受入条件を先に記録する。
2. ローカルで開ける高品質HTMLプロトタイプを作成する。Home、Conference準備/字幕、Meeting準備/Live/Review、Floating、Sessions、Settingsを扱う。
3. ライト/ダーク、狭幅、文字拡大、主要操作とエラー復帰をブラウザで検証し、代表画面を保存する。
4. 計画のPR5-AをREVIEWへ更新し、ユーザーがモックをレビューする。承認まではPR5-B/Cへ進まない。

## 成果物

- `app-information-architecture.md`: コードからの観察、画面マップ、旧新対応、段階別範囲。
- `design-system.md`: 色・文字・余白・コンポーネント・サイズ・操作ルール。
- `ux-states-and-flows.md`: フロー、状態表、受入チェック、設計判断。
- `mockups/index.html`: 架空会議データだけで操作するモック。音声取得・LLM通信・実データ保存は行わない。
- `validation.md`: 実施した検証と未検証事項、承認対象。

## 境界

本作業は設計・試作。Swift製品コード、保存形式、音声経路は変更しない。TDDの製品実装フェーズはPR5-B/Cの計画承認後。ブラウザ上の操作確認とmacOSネイティブ受入は区別する。ユーザー調査・VoiceOver・画面共有・音声試験を実施したと記載しない。

## 受入

必須画面と正常/空/準備/権限拒否/入力断/AI停止/オフライン/停止失敗を閲覧できる。Conference既存操作への対応が追跡できる。候補の確認/却下、根拠表示、送信許可、停止/再開のフローを試せる。結果と制約を明示してモック承認待ちにする。
