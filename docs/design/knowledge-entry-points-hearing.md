# 資料の追加・選択導線 — ヒアリング

日付: 2026-11-12 / 基準: ローカルmain `56d7a81`
状態: 用途確認済み。ユーザー「1,2,3」により3用途を選択し、続く「承認」で実装計画を承認。Meeting／Conferenceの最中にも資料追加できることを再確認。ローカル実装・主要検証済み。実音声・実モデル品質評価は継続。

## ユーザーの要望

- Meeting準備時に資料を追加できる導線。
- 資料ライブラリ画面で、会議より前に資料を追加できる導線。
- MeetingとConferenceで資料を追加・選択できるようにする。

## 現在の実装

- `MeetingKnowledgeControls`は準備画面だけでファイル追加とライブラリ選択を表示する。
- `MeetingWorkspace.importKnowledge`と`KnowledgeLibrary.canUse`も準備中・idleに制限している。ボタン表示だけを変更しても実行中の追加はできない。
- `KnowledgeLibraryView`には一覧・検索・閲覧・削除があるが、新規資料の直接取り込みはない。保存元はMeetingに結びついている。
- Conferenceの準備・字幕画面には資料の追加・選択機能がない。
- 現行の取り込み形式はMarkdown/Textとリポジトリ。PDF/OCRは未実装。

## 導線案（提案）

| 場所 | 操作 | 結果 |
|---|---|---|
| 資料ライブラリ | ファイル／リポジトリを追加、保存名を指定 | 会議を作らずMac内に保存し、後から選べる |
| Meeting準備 | ファイル／リポジトリを追加、ライブラリから選択 | このMeetingの参照資料へ追加 |
| Meeting実行中・一時停止中 | 同じ追加・選択操作 | 文字起こしを継続しながら参照資料を追加 |
| Conference準備・実行中・停止中 | ファイル／リポジトリを追加、ライブラリから選択 | このConferenceの資料として保持。利用方法はQ1で確認 |

- 直接取り込みと保存版の選択を、各画面の「資料」領域から見つけられるようにする。
- セッションへ直接取り込んだ資料のライブラリ保存は明示操作とし、従来の保持方法を継続する案。
- ライブラリの更新・削除は使用中のセッションのコピーや既存の引用を変更しない。
- MeetingとConferenceの資料選択は別々に保持する。
- 実行中の追加は、開始・終了処理中や別の取り込みとの競合を制御する。録音停止操作は妨げない。
- Meetingでは資料変更後に送信許可を見直し、旧資料への処理結果が新しい状態へ混入しないようにする。
- 終了後の編集・選択資料のSessions永続化の範囲は、用途確定後の実装計画で明示する。

## Q1: Conferenceで資料をどう使うか

| 選択肢 | 範囲 |
|---|---|
| 閲覧・検索（推奨） | 字幕・翻訳と並行して資料を開き、ローカル検索する |
| 閲覧・検索＋AI質問 | 選択資料へ質問し、根拠付き回答を得る機能も追加する |
| 文字起こし・翻訳の精度改善 | 資料の用語や文脈を認識・翻訳へ反映する。実現方式と評価条件の追加調査が必要 |

回答: ユーザー「1,2,3」。3用途すべてを対象にする。[実装計画案](knowledge-entry-points-implementation-plan.md)へ反映。用途選択を計画全体の承認としては扱わない。

Meetingの用途は既存のAI回答・自動提案・要約への資料参照を継続する。開始前だけでなく実行中にも追加・選択できる想定を質問とともに提示済み。

## 用途に依存しない実装・検証の論点

1. ライブラリへの取り込み・保存処理をMeetingが存在しなくても使用可能にする。
2. 保存名、対象選択、容量上限、失敗時の既存保存保持、重複・更新の扱いを既存仕様と揃える。
3. ライブ追加の開始から完了までにセッション終了・破棄が発生した場合、次のセッションへ追加しない。
4. 資料追加中も音声取得・文字起こしを継続し、停止を可能にする。
5. 追加・選択・取り外しと既存引用、ライブラリ更新・削除の独立性を検証する。
6. 準備・実行中・一時停止・終了・失敗状態と、狭幅・キーボード・VoiceOverの操作を確認する。
7. 実装は資料更新→TDD→最小実装→lint・関連/回帰テスト・UI確認の順に行う。
