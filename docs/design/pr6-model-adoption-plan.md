語句検査やXCTest成功だけで意味を合格にしない。通信失敗・打切りは意味不合格と区別するが、全件成功には数えない。失敗はそのまま報告し、同じ枠で修正後の再評価を重ねない。

## 新ビルドの非録音受入

- 無通信プレビューで言語の選択、設定とMeetingの共有、終了・再起動後の復元を確認。プレビュー専用UserDefaultsを使用する。送信中の変更は次要求へ適用されることを既存テストとUIで確認する。
- 新ビルド自身で既存キーの読出し・登録状態を確認。既存の読出し許可を再質問しない。OSが新たな認証を要求した場合だけユーザーによるOS操作が必要。旧ビルドの成功で代用せず、キー変更・削除はしない。
- 製品View/クライアント/transportと合成音声源で、主画面AI停止、小窓AI停止、一時停止、会議終了の4操作を受信中に行う。部分回答保持・取消・停止後の新規送信なしを確認。`firstChunk < click < end`と取消を根拠とし、人工遅延を加えない。
- **UI最大8要求**: 4取消操作＋再開後の正常完了1件を優先し、残り最大3件をタイミングが合わなかった場合の試行に充てる。失敗も枠に含め、品質枠とは融通しない。完了後クリックを受信中停止合格に数えない。
- キーボードで回答言語と主要操作へ到達できること、狭幅・大きい文字で状態/停止操作が使えることを無通信で確認。VoiceOverの実読み上げも利用可能なら確認し、AX取得だけで合格にしない。
