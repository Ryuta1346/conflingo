状態: **2026-11-11、ユーザー「進めて」により計画承認済み。実装・自動検証・主要UI確認済み。S12の残る実操作は未完了。**

## 目的と範囲

利用者が保存した会議・字幕を、アプリを終了しても失わず、一覧から再び読めるようにする。既存の承認モックに合わせ、**MeetingとConferenceの両方**を対象にする。

| 機能 | 今回の契約 |
|---|---|
| 保存 | Meetingは会議終了後、Conferenceは停止後に「このMacに保存」を明示操作。自動保存はしない |
| 一覧 | 「保存したセッション」に種別・名前・開始日時・保存更新日時を表示。保存更新日時の新しい順 |
| 検索 | セッション名の部分一致。空欄で全件、日本語と英字を扱い、英字の大文字小文字を区別しない |
| Home | 最近保存した5件と「すべて見る」を表示。0件なら空状態 |
| 再読込 | 保存した内容を読み取り専用画面で表示。音声・翻訳・AIは自動開始しない |
| 出力 | 保存内容から既存形式のMarkdownを再出力。アプリ内保存とは状態・操作を分ける |
| 削除 | 対象名を示す確認後にアプリ内保存だけ削除。外部Markdown・元資料は変更しない |

再読込した記録の編集・AI再生成・録音再開、クラウド同期、自動保存、PDF/OCR、永続資料ライブラリ、一般のファイルからのセッションインポートは今回含めない。セッション名検索を会話本文の全文検索とは表示しない。

## 保存する情報

### 共通

- 保存形式の版、UUID、種別、タイトル、開始日時（不明なら不明のまま）、保存作成/更新日時、言語設定。
- 保存対象は、明示操作時に画面の元データから作成する不変のスナップショット。保存中の変更は同じ保存成功に含めない。
- 初版でセッション履歴の既存保存形式はないため、仮想的な旧形式の移行処理は追加しない。辞書・設定など既存データは維持する。

### Meeting

- 入力元・言語・時刻・IDを含む確定発話。
- 完成したAIカード、決定/アクション候補の未確認・確認済み・却下状態、発話への根拠ID。
- 最後に完成した区間別要約と回答言語、資料由来の補足。
- 保存するカード・候補・要約が引用した資料の抜粋、資料名、行/位置、取り込み日時、リポジトリ相対パス・内容ハッシュ・snapshot ID。
- 途中の音声認識、生成中/中断カード、未完成要約は保存しない。再生成失敗時は既存の完成版だけを保存する。
- 元資料を取り外したり元リポジトリが変化しても、保存時の引用抜粋を読める。資料全体、検索索引、絶対パス、APIキー、送信許可は保存しない。

### Conference

- 確定セグメントと翻訳単位、それぞれのID・時刻・対応、取得済み訳文、未翻訳/失敗の区別。
- 文字起こし専用か翻訳モードか、および保存時の原文/訳文言語設定。現在のMarkdownの扱いを継承する。
- 入力停止後も翻訳の結果が到着し得るため、保存時点の状態を記録する。処理中は保存詳細で「保存時点で未完了」と示し、自動的に翻訳し直さない。
- 停止後に訳文が増えた場合は「保存後に変更あり」と表示し、明示的な再保存で更新する。partialは含めない。

保存前の説明に、発話・AI出力・引用抜粋をこのMacに保持することを明記する。音声ファイルとAPIキーは対象外。アプリ独自の暗号化・バックアップ管理は追加せず、ローカル保存を「暗号化保管」や「安全な完全消去」と表現しない。

## 保存と画面の設計

1. `Sessions/`配下に版付きの保存モデル、ファイル保存actor、画面状態、一覧・詳細Viewを置く。保存モデルは実行中controllerやAI clientを持たない。既存の値型の利用を優先し、永続化の都合で不要な汎用repository層やフレームワークを追加しない。
2. Sandbox内のApplication Support配下に専用ディレクトリを作り、1セッション1 JSONファイルで保持する。ファイル名はUUIDからのみ生成し、会議名や資料パスをパスに使わない。依存ライブラリ、DB、マイグレーション基盤は追加しない。
3. ファイル操作はUIスレッドから分離し、保存・更新・削除を直列化する。書き込み成功後にだけ保存済み表示と一覧を更新。原子的な置換を使い、失敗時は既存の保存版とメモリ上の会議を保持する。
4. 同じセッションの再保存は同じUUIDを更新し、二重クリックで重複を作らない。Clear/reset後は新しい記録になる。古い保存処理の完了が新しい会議を「保存済み」にしないよう、IDと保存対象の一致を確認する。
5. 保存中は対象のリセット/破棄と重複保存を抑止。停止・終了・要約生成などの遷移中はMeetingの保存を無効化する。Conferenceは入力のidleが前提。保存後の候補確認変更も未保存変更として扱う。
6. Sessionsの閲覧は現行Meeting/Conferenceの内容を置き換えない。進行中の音声からSessionsへ移動する場合は既存の停止確認を通す。戻ったときの会議・字幕を保持する。
7. 詳細画面は保存日時と読み取り専用を示し、発話根拠と引用抜粋を参照できる。AIによる生成物の未確認表示を維持し、確認状態を再計算・自動確定しない。
8. 壊れたファイル・未知の保存版は一覧全体を失敗させず、該当記録の読込失敗を表示。自動削除・上書き・捏造復旧は行わない。形式、種別、ID重複、session所属、時刻値、根拠参照の整合を検証し、不正データでcrashしない。
9. 削除成功後に一覧・Home・開いている保存詳細から対象を外す。取消・削除失敗では保持。元の会議がメモリに残っている場合、その内容は消さず「未保存」に戻す。以後の明示保存では再保存できる。
10. 一覧は必要な概要を表示し、全記録のViewを一度に描画しない。検索/読込の古い非同期結果で新しい選択や削除結果を上書きしない。大規模DB化は実測で必要になるまで行わない。

## 受入条件とテスト

| ID | 受入条件 | 検証 |
|---|---|---|
| S01 | 未保存の会議は再起動後に一覧へ現れず、明示保存した両モードだけ復元される | 一時ディレクトリとstoreの新規生成、無通信アプリ再起動 |
| S02 | 発話・訳文・候補状態・完成要約・引用出典が保存前後で一致する | 日英・文字起こし専用・失敗訳文・資料付き要約のround-trip |
| S03 | 通常回答を含む完成カードは閲覧でき、partial/未完了要約・許可・キーを保存しない | 保存内容と再表示を公開API経由で検証 |
| S04 | 同一会議の再保存で重複せず、reset後は別記録になる | 再保存・二重操作・遅延完了・削除後の明示保存 |
| S05 | 保存失敗で旧版を失わず、成功と表示しない | 書込/置換失敗の注入と実ファイル再読込 |
| S06 | 壊れた1件や未知版が正常な他の記録を妨げず、元ファイルを変更しない | 混在ファイル、無効ID/時刻/参照のfixture |
| S07 | 名前検索・新しい順・Home最近5件・空状態・読込失敗を表示できる | 日英タイトルと0/1/複数件の状態テストとUI |
| S08 | 閲覧でマイク・内部音声・翻訳・AI送信が開始せず、現在の会議を破壊しない | controller/clientの呼出し監視、停止確認の回帰 |
| S09 | 再出力の内容が保存時の既存Markdown規則と一致し、取消/失敗を扱える | 両exporterの比較、OS保存パネルの合成操作 |
| S10 | 削除は対象だけに作用し、外部Markdown・元資料は保持される | 取消/失敗/成功、一時ファイルと詳細画面の整合 |
| S11 | 保存後の変更を検出し、遅延結果で誤った保存済み表示を出さない | 翻訳追加・候補状態変更・要約更新・resetとの競合 |
| S12 | 狭幅・拡大文字・キーボードで保存/検索/閲覧/引用/削除に到達できる | 既存モックとの比較、ネイティブUI・VoiceOver可能範囲 |

保存処理のテストはfakeだけでなく一時ディレクトリで実ファイルI/Oを行う。UI検証は別bundle ID・専用保存先と合成データを使い、利用者の既存データを読み書きしない。100セッション程度の合成データで一覧・検索・詳細表示の応答時間とメモリを記録し、目立つ停止があれば完了前に対応する。長時間実会議の性能受入とは区別する。

## 実装順序

1. 承認結果を本計画・ヒアリングへ記録し、詳細計画、情報設計、保持/破棄説明、進捗表を更新。旧記録は実施当時の証跡として保持する。
2. 保存/再読込・失敗時の保持・削除の振る舞いからTDDで実装。続いてMeetingとConferenceの保存境界、再保存状態を接続する。
3. 一覧・検索・最近の保存・読取専用詳細・根拠表示・Markdown再出力を実装し、停止確認と既存画面の回帰を確認。
4. 全テスト、SwiftLint `--no-cache --strict`、Debug/Releaseビルド、差分チェック、無通信のネイティブUIを実施。現在の406テスト記録は参考値で、変更後の新規結果を残す。
5. 保存/削除/競合/根拠のレビューと不要なコード・説明の整理を行い、`docs/validation/sessions.md`に結果と未検証事項を記録する。独立レビューを行っていなければ明記する。

各テストは期待する理由でRedを確認してから最小実装する。TDD実行前にスキルの専門観点を確認する。関連テストでGreenを確認した後、最終の全体検証を行う。無関係な既存変更は戻さない。

今回は単一の機能として計画し、未完成の保存UIだけを公開しない。コミット・push・PR作成・マージは本計画の承認に含めず、明示依頼がある場合のみ実施する。

## リスクと今回の完了範囲

- 既存Markdownは汎用回答カードを出力しない。Sessionsでは閲覧できるが、既存出力形式の拡張は行わない。
- 取り込んだ全資料を保存しないため、再読込後の検索やAI再質問はできない。引用した抜粋の再閲覧を保証する。
- 未保存の内容はアプリ終了/クラッシュで失われる。自動保存・クラッシュ復旧を実装済みとは表示しない。
- 実API要求・実音声取得はこの計画に不要であり実施しない。既存Gate A/B/C/U/D、実請求額照合、配布署名、全体の60分耐久は引き続き別の残件。
- 今回の完了はS01〜S12の結果とlint/test/build/UI証跡で判断する。Sessions実装を理由に既存受入完了数2/12を増やさない。
