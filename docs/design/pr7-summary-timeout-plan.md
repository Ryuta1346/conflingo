## 追加する計測

製品の`URLSessionInsightTransport`をそのまま使い、評価側のwrapperと既存の公開callbackで計測する。接続実装の置換や本文の改変は行わない。

| 記録 | 起点／用途 |
|---|---|
| client開始、transport到達 | 資格情報読取と要求組立を含む前処理の時間を区別 |
| count開始／完了 | token計数の待ち時間と結果token数 |
| generation開始 | 予約永続化後、製品transportを呼ぶ直前 |
| firstChunk、lastChunk、chunk数、累積byte数 | 製品transportからデコーダへ最初／最後に渡ったデータ。生のソケットの初回byteとは区別 |
| firstPreview、最大preview文字数 | 製品clientの更新callbackで初めて非空の回答断片が得られた時点。断片本文は保存しない |
| stream終了／decode・使用量確定 | ネットワーク完了と結果処理を区別 |
| 観測通知開始／完了 | loopback送信待ちを生成時間と分ける |
| 終了／例外／coordinator状態 | 成功だけでなく取消・timeoutでも、既に観測した時刻・量を残す |

- 経過時間は単調時計を使用する。開始日時は照合用に別記録する。
- 未到達の時刻はnullとして保存し、0秒と解釈しない。stage順序と値の整合をローカルテストする。
- chunkごとの本文保存や同期ファイル書込はしない。メモリ上のカウンターを更新し、要求終了・取消時にメタデータを保存する。計測保存に失敗した場合は後続を送らない。
- 取消済みTaskでもタイミングを保存できるようにし、後続の通信や再送を発生させない。外部から読めるエラーは既存のサニタイズ済み分類だけにする。
- `firstChunk`は製品transportの改行／1024byteバッファ後の観測。DNS・TCP・TLS・HTTPヘッダーの個別時間は取得しない。これだけで接続障害とモデル処理を断定しない。
- 生成開始からfirstChunkがないままtimeoutした場合は「最初のデータ受領前に停止」、受領後なら「ストリーム受領後に停止」と記録する。思考時間はusageが得られた場合のtoken数から記述し、待ち時間から推測しない。
