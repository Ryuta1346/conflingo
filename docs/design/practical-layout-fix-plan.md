# 実用確認で見つかった狭幅字幕の修正計画

## 問題と到達条件

約742×562ptの主画面で、Meetingの字幕本文が約1行まで縮み、最新へ移動すると余白だけになる。Conferenceも原文・訳文が行途中で切れる。上部のConferenceラベルも単語途中で改行する。狭幅で両ペインを縦に並べた際の高さ不足が原因候補。

既存の通常幅表示を維持し、640×520pt以上のウィンドウで本文をスクロールして読めるようにする。狭幅でも全情報を同時に詰め込まず、原文・訳文・AI支援に順番に到達できる表示とする。

## 変更範囲

- `ConfLingo/Meeting/Views/MeetingWorkspaceView.swift`: 縦配置時に字幕本文と支援欄へ最低限の高さを割り当て、収まりきらない場合は外側の縦スクロールで到達できるようにする。通常幅の横2ペイン、履歴の選択・最新追従、画面サイズ変更前後の会議/ScrollViewの同一性を維持する。
- `ConfLingo/Conference/Views/ConferenceLiveView.swift`: 原文・訳文ペインをヘッダー込みの60ptまで圧縮しない。文字サイズに応じた本文領域を確保し、低い画面では縦スクロールで両方へ到達できるようにする。
- `ConfLingo/App/AppShellView.swift`: 狭幅ナビゲーションのラベルを1行表示にし、横幅不足時はナビゲーションを横スクロールで到達可能にする。各ボタンの名称・アクセシビリティ名は維持。
- 字幕コンポーネントへの変更は、上記の高さ確保だけで解消できない場合の最小範囲に限る。音声処理、AI送信、保存形式には変更を加えない。

## 実施順序

1. 本計画承認後に関連設計・受入条件を先に更新する。
2. tddスキルに従い、主画面全体を使う再現テストを追加し、現状で失敗することを確認する。単体字幕に十分な高さを与えたテストだけでは代用しない。
3. 本文領域の最小高さと必要時のスクロールを最小実装し、既存のスクロール位置・表示同一性テストを維持する。
4. 全テスト・Lint・Releaseビルド後、実画面で通常幅→狭幅→通常幅、末尾追従、根拠への移動、原文・訳文・支援への到達を再確認。検証記録とplan.mdを更新する。

## 受入条件

- Meetingのライブ/振り返り、Conferenceの翻訳/文字起こし専用を対象にする。
- 1180×780pt、742×562pt、640×520ptで、文字サイズ16/32/48ptを確認する。
- 字幕本文のスクロール表示領域に少なくとも複数行が入る高さを確保し、最新へ移動した後も本文の末尾が見える。余白だけを「最新」として表示しない。
- 長文はスクロールして読める。原文・訳文の両方と、AI支援・保存・停止操作へ到達できる。
- 狭幅から通常幅への変更で履歴位置・選択根拠・会議内容を失わず、入力の再開始や追加送信を起こさない。
- Conferenceのナビゲーションラベルを単語途中で改行しない。全6項目をクリック/キーボードで選択できる。
- 実APIや実音声は不要。合成データと専用プレビューで再現・検証する。
