## 質問1: 初回の4要求を実行してよいか

提案: 既存のGemini `gemini-3.8-flash` に、次の4要求だけを送る。APIキーの登録・変更やモデル切替は行わない。利用できない場合は停止し、他モデルへ自動代替しない。

| ケース | 送信内容 | 上限 |
|---|---|---|
| 長い要約・日本語 | 架空の会議30発話以内、合計6,000文字以内。決定・担当・未決事項を詳しく要約 | 1生成要求 |
| 長い要約・英語 | 同じ架空会議の英語版。合計6,000文字以内 | 1生成要求 |
| Web調査・日本語 | 公開情報だけを対象に「HTTPのETagとIf-None-Matchによるキャッシュ検証の仕組みを、公開仕様を根拠に説明」 | 1生成要求 |
| Web調査・英語 | 同じ質問の英語版 | 1生成要求 |

共通条件:

- 会議・保存セッション・資料・リポジトリ本文は送信しない。通常の製品システムプロンプトと合成入力だけを送る。
- 生成APIは合計最大4要求、各ケース1回、逐次実行、再試行0。出力上限は各8,192 tokens以下、合計32,768 tokens以下。HTTP本文は各32,768 bytes以下、各60秒。価格・実請求の保証ではなく要求枠の提案。
- Web検索はGemini内蔵検索を2生成要求で使用する。プロバイダー内部の検索回数を「2回」とは扱わない。課金対象となる可能性がある。
- 計測用の受信は最大8 MiB/要求・最大行/イベント1 MiBで打ち切る案。製品の上限は変更しない。計測は返却済みバイトの数値集計とデコードに限定する。
- 記録はモデル、ケースID、受信量、復号本文量、最大行/イベント、イベント数、usage、所要時間、終了/失敗区分だけ。応答本文・キーは保存/ログ出力しない。
- 失敗・取消でも送信済み要求は消費扱いとする。使用量不明の場合はその旨を残して後続送信を止める。

回答欄: **承認 / 条件変更 / 実APIを使わずローカル修正を先行**。

## 質問2: Gemini以外の実測対象

OpenAI・Claude・Kimi・DeepSeekは、今回の読み取りで使用モデルを特定できていない。既存の認証情報を読み出す前に、測定対象とモデル名を確定する。質問1の承認を他社への送信許可として流用しない。

回答欄: **まずGeminiのみ / 対象プロバイダー・モデル名を指定**。

その他互換クラウド・ローカル接続は送信先も個別指定が必要。全社の実測が揃うまでは、未測定として残す。
