## 利用者に見える変更

- 取り込み済みのローカルリポジトリとMarkdown/Textを、自動提案でも参照できる。
- 「自動提案にも資料を使う」を追加し、初期値はオフ。手動質問の資料許可と終了後要約の選択から独立させる。AI送信許可と自動提案が有効なときだけ利用できる。
- 許可した場合、提案対象になった確定発話からローカル検索し、関連する抜粋だけを既存の生成要求に添える。検索用の追加LLM要求は発生しない。入力トークンは増える場合がある。
- 提案カードから資料名、相対パス、行番号、取り込み時点の版を確認できる。会議の発言と資料由来の根拠を区別する。

## 調査で確認した変更箇所

| 現在の実装 | 変更 |
|---|---|
| `InsightRequest`がautomaticの資料を常に空にする | トリガーによらず共通の抜粋上限を適用し、送信可否はcoordinatorで判定 |
| `InsightCoordinator.receive`が検知後すぐ生成する | 許可時のみ非同期のローカル検索を挟む |
| `canAsk`が全検索中にfalseになる | 自動検索・自動生成を手動質問が中断できるよう、処理の種類を区別 |
| 自動提案の停止は生成中のrequestを対象にする | 検索中も取消・遅延結果の棄却対象にする |
| 手動資料許可と要約専用の選択がある | 自動提案の独立した許可と失効処理を追加 |

## 検索・送信の契約

1. 確定発話、許可後の時刻、既存の質問・懸念・決定等の検知条件を維持する。許可をオンにしただけでは過去発話を送らない。
2. 同一イベント・類似文の重複抑止、60秒あたり最大2回、最短12秒間隔、同時処理1件を維持。検索開始前に枠を確保する。取消・失敗分を自動再試行せず、処理中の新規イベントを未処理キューに蓄積しない。
3. 検索語は固定の提案依頼文ではなく、検知対象の確定発話から作る。生成に含める発話と同じ最大12,000文字の範囲で、2,000文字単位に検索し、重複を除いて順位を統合する。2,000文字を超える部分も対象にする。
4. 送信抜粋は最大5箇所・各1,200文字・合計6,000文字。既存のパス・行番号・内容ハッシュ付き引用を利用する。元の絶対パスを送らない。
5. 一致なしは資料なしの通常提案に進む。検索失敗は一致なしと区別し、そのイベントでは送信せずエラーを表示して自動提案を停止する。
6. 検索開始時のセッション、発話、回答言語、資料revision、許可状態を固定する。送信直前に有効性を再確認する。
7. 自動提案は検索開始から生成完了まで合計30秒で打ち切る。検索後に期限を延長しない。手動回答30秒、終了後要約60秒の契約は維持する。
8. 検索は音声・文字起こし・イベント購読を待たせず、保持した取消可能なTaskで実行する。手動質問は自動検索・自動生成を中断して開始できる。古い処理の完了が新しい手動処理を取り消さないよう処理IDを検証する。

## 許可と取消

- AI送信許可解除・キー変更／削除・会議リセットで自動資料許可も解除する。
- 自動提案オフ、自動資料許可オフ、資料追加／削除／差し替え、一時停止、終了、セッション変更、購読overflowでは、該当する自動検索・生成を取り消す。遅れて返る検索・生成結果は採用しない。
- 自動資料許可だけの解除は手動回答と要約の許可を変更しない。解除後の新規自動提案は発話のみで動作できる。
- 回答言語変更は既存の「次の回答から反映」に合わせ、開始済みの処理は固定済み言語を使用する。
- 完成済みの提案と引用は会議破棄まで保持する。停止により送信済みの内容を外部から回収できるとは扱わない。

## 応答と表示

- 既存の資料を根拠データとして扱う指示、コード・テスト・設計の区別、取り込み時点の作業ツリーという表示を再利用する。
- 資料の存在だけで会議の合意・担当・期限を確定しない。候補の確定は既存の利用者操作を維持する。
- 未送信の資料IDを引用した応答は既存の無効根拠処理で拒否する。自動提案の応答スキーマは既存の手動支援と共通にし、要約専用のsupplementは追加しない。
- AI設定の送信説明・資料許可UI・処理状態・利用ガイドを更新する。

## 実装と検証

承認後、関連資料を更新し、以下をTDDで実装する。実装前に失敗を確認してから最小の変更を加える。

| 対象 | 受け入れ条件 |
|---|---|
| 許可 | 初期オフ、3種類の資料許可の独立、AIオフ／リセットで失効。無許可の自動要求に資料が含まれない |
| 検索 | 発話の識別子・パスからコードを検索。2,000文字以降の一致、通常資料との混在、重複・上限、一致なし／失敗を確認 |
| スケジューリング | 発話確定条件・時刻・頻度上限・重複抑止・同時1件を検索中にも維持。手動質問が自動検索／生成に優先 |
| 取消 | 検索中／生成中の停止・許可解除・資料変更・終了・overflow・deadlineで遅延結果を棄却。新しい要求への干渉なし |
| 引用 | 送信した資料だけを引用。作業ツリーと会議発言の区別を保持。引用表示とMarkdown出力を確認 |
| 回帰 | 既存の手動質問・資料付き要約・候補管理・文字起こしのテストを実行 |

変更対象: `KnowledgeStore`、`InsightRequest`、`InsightCoordinator`、Meetingの設定接続・AI/資料UI、対応テスト、無通信プレビュー、利用ガイド・検証記録。

検証は合成資料・fake clientで行い、関連テスト、全テスト、lint、Debug/Releaseビルド、無通信UIの許可・自動提案・引用・停止を確認する。基準は既存機能394テスト／67 suitesの[検証記録](../validation/repository-knowledge.md)。既存記録は履歴として保持し、追加分の結果は別に記録する。

実APIでの意味的品質と実音声結合は別工程。今回の実装・ローカル検証で利用者のコードをAPIへ送信しない。Gitコミット・PR作成・マージは本計画に含めない。
