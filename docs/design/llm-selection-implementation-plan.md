# クラウド／ローカルLLM選択 実装計画案

日付: 2026-11-12 / プロジェクト: conflingo / 現在ブランチ: feature/llm-selection
状態: 2026-11-12 ユーザー「OK」により更新版承認済み。コード実装・自動テスト・ローカル模擬接続検証を完了。実クラウド／Qwenの生成品質は未検証。結果は `docs/validation/llm-selection.md` を参照。以下は承認時の実装計画。
正本保存先: `~/.coding-agents/docs/conflingo/feature-llm-selection/llm-selection-implementation-plan.md`

## 目的と提案範囲

利用者がGemini / OpenAI / Claude（Anthropic）/ その他クラウドLLM / ローカルLLMから接続先とモデルを選ぶ。Meetingの手動質問、自動提案、資料参照、要約で同じ選択を使用する。ChatGPTログイン・サブスク認証は今回の対象から除外する。

| 選択肢 | 接続方式 | 設定 |
| --- | --- | --- |
| Gemini | Google公式API | APIキー・モデル |
| OpenAI | OpenAI公式Responses API | APIキー・モデル |
| Claude | Anthropic公式Messages API | APIキー・モデル |
| Kimi / DeepSeek | 各社公式のOpenAI互換API（設定プリセット） | APIキー・モデル |
| その他クラウドLLM | OpenAI互換Chat Completions API | 表示名・Base URL・APIキー・モデル |
| ローカルLLM（Qwenなど） | PCに導入したモデルをOllama / LM Studio等で実行 | ローカル接続先・導入済みモデル・必要ならAPIキー |

ユーザーが具体例として指定したKimi・DeepSeekを初回対応の明示対象とし、URLや出力方式をプリセットで用意する。他のOpenAI互換クラウドもカスタム接続で追加できる。ローカルは利用者のPCに導入したQwen等のモデルを対象にする。Qwenはモデル、Ollama / LM Studioはその実行・API公開を担うソフトとして区別する。既存実行ソフトへ接続する案で、利用者の実行環境はまだ未確認。互換APIでない独自プロトコル、AWS/Azure固有の署名認証、モデルのダウンロードや推論エンジンのアプリ内蔵は初回範囲外。ローカルは同じMac上のサーバーへの接続を初回範囲とする。これらの具体化は今回提示する設計案であり、利用者が指定した全サービスへの対応が確認できたという意味ではない。

## 現状

- `InsightClient` は共通境界として使用できる。
- `MeetingWorkspace` が `GeminiInsightClient` を生成し、質問と要約へ共有する。
- `GeminiInsightClient.model` が固定。`GeminiCredentials`、設定画面、送信許可・要約確認・エラー文言もGemini専用。
- `URLSessionInsightTransport` はGoogleのホストだけを許可する。
- キーはKeychain、選択・画面設定はUserDefaults。保存会議に認証情報や送信許可を含めない。
- macOS App Sandbox有効。ネットワークclientは有効だがserver entitlementなし。

## 設計案

### 設定と認証

- 設定に接続一覧・追加・編集・選択を用意し、提供元、表示名、Base URL、モデル、接続状態を表示する。複数のカスタム接続を保存可能にする。APIキーは接続ID別Keychain項目で保存・削除する。既存Geminiキーのservice名を維持し、再入力を不要にする。
- 選択情報だけをUserDefaultsへ保存。既存利用者の初期値は現在のGeminiモデル。選択モデルが使えないときは明示エラーとし、別モデルや別課金方法へ自動切替しない。
- API接続ではモデル一覧APIが返す候補を表示し、出力方式の対応は接続確認で検証する。モデル一覧APIの存在だけで構造化出力等に対応済みと扱わない。具体的なモデル候補と各社API仕様は実装開始時の公式資料で確定する。
- モデル一覧を取得できる接続では候補を表示する。一覧非対応・取得失敗の場合もモデルIDの手入力を可能にする。接続確認はユーザー操作で合成文を1回生成し、認証だけでなく必要な出力形式まで確認する。課金される場合があることを操作前に表示する。
- カスタムURL変更時は以前のキーを新しい接続先へ自動転送せず、キーの再設定を必要とする。キーを消すときは該当接続のキーだけを削除する。
- 認証・接続URL・提供元・モデルの変更は処理をキャンセルし、送信許可と要約確認を失効させる。以前の応答が切替後に画面へ混入しないよう要求単位で設定を固定する。

### クライアントと既存機能

- `InsightClient` を維持し、Gemini / OpenAI Responses / Anthropic Messages / OpenAI互換Chat Completionsのアダプタを置く。その他クラウドとローカルは互換アダプタを共有する。
- 既存プロンプトの根拠・回答言語・資料引用の契約を維持する。共通化は実際に共有する入力整形・結果検証に限定する。
- 公式接続は公式ホストへ、カスタム接続はユーザーが保存した正規化済みBase URLへ限定する。URL内のユーザー情報・query・fragmentを拒否し、パス接頭辞を保持してAPIパスを構成する。リダイレクト拒否、機密情報を含めないエラー、受信サイズ制限を維持する。
- 現行の30秒／要約60秒、停止連動、無断再送なし、自動提案の頻度制御を維持する。
- 画面・同意文・要約確認・診断表示は実際の提供元と課金方法を表示する。

### その他クラウド・ローカルの互換性

- クラウドURLはHTTPS、同じMacのループバック宛てはHTTPを許可する。ローカルHTTPに必要なATS設定を最小限に調整し、署名済みSandboxアプリで接続を検証する。アプリからサーバーを起動したりモデルをインストールしたりしない。
- ローカル接続ではAPIキーを任意にし、未設定ならAuthorizationヘッダーを送らない。ネットワーク上の別PCへの平文HTTP接続は初回範囲外。
- 「ローカル」は接続先の分類であり、接続先サーバーがクラウドへ転送しないことまでは保証しない。送信許可には実際の接続名・URLを表示し、アプリからクラウドへの自動切替は行わない。
- Kimi / DeepSeekは公式仕様に沿う出力方式・必要なパラメータをプリセットに設定する。推論用のreasoningフィールドを回答本文へ混ぜず、本文のJSONを検証する。モデル別の必須パラメータとJSON制約をHTTP契約テストで確認する。
- 互換接続の出力方式を「JSON Schema / JSONモード / プロンプト指定JSON」から明示設定できるようにする。既定はJSON Schema。利用できない方式で失敗した場合は自動再送せず、利用者が方式を変更して接続確認する。
- どの出力方式でも本文・種別・根拠ID・資料IDを共通検証する。不正JSONを失敗とし、未知のIDは既存仕様どおり引用から除いて警告する。要約は未知IDを含む応答を拒否する。生成品質・速度はモデルごとに検証し、全モデルで同品質とは表示しない。
- 接続先ごとのストリームを共通結果へ変換する。完了前の切断、空応答、出力打切りを失敗として区別し、使用量非対応は「不明」と扱う。
- ローカルのモデル未起動・モデルID不正・遅延は明示エラーにする。現行時間制限を初期値として維持し、許容時間の変更は必要性が確認された時点で別途判断する。

## 実施順序

1. 更新版計画を承認。要件・設計に「予定」として追記し、実装済み記述とは分ける。
2. TDDで設定・Keychain分離・切替時取消の振る舞いを先に検証し、既存Geminiを選択式へ変更。
3. OpenAIとAnthropicのアダプタ、モデル選択、画面・同意文を実装。HTTP境界のモックテストを先行。
4. Kimi / DeepSeekプリセット・OpenAI互換アダプタ・カスタム接続管理・ローカルHTTP・出力方式設定をTDDで実装し、Sandbox環境でローカル接続を検証。
5. lint・関連テスト・既存回帰・UI操作を検証し、利用ガイドと検証記録を実装結果に合わせ更新。不要になったGemini専用の重複コード・文言を整理。

各段階で既存Geminiが動作する状態を維持。未完成の接続先は選択可能にしない。コミット・PR作成は別途ユーザー指示時のみ。

## 受入条件

- Kimi / DeepSeekをプリセットから追加し、各社のキーとモデルで要求を構成できる。ローカル接続ではPCに導入済みのQwen等をモデル一覧またはモデルIDで選べる。Qwenのモデルファイルを直接読み込むエンジン内蔵方式は今回の提案に含めない。
- 再起動後も接続先・モデル・出力方式が復元され、対応するキーだけを送信する。
- 手動質問・自動提案・要約・資料参照すべてに選択が適用される。キー変更・削除、接続先／モデル切替中の結果混入を防ぐ。
- ストリーム分割、構造化出力不正、拒否、途中終了、401/403/429、取消、上限到達、互換APIの未対応パラメータ、ローカル未起動をテストする。
- カスタム接続間でキーが混ざらない。URL変更時に古いキーを送らない。ローカル未認証接続にAuthorizationを付けない。
- `/v1`等のBase URLパス、末尾スラッシュ、IPv4/IPv6ループバック、リダイレクト拒否、非許可HTTPをテストする。
- モデル一覧非対応でも手入力でき、未対応の出力方式を明示する。自動でモデル・接続先・出力方式を切り替えて再送しない。
- 現行Geminiキー・保存会議・資料ライブラリを維持。キー・トークン・許可情報を会議保存・Markdown出力・ログへ含めない。
- Conferenceのローカル字幕・翻訳とMeetingの音声処理が回帰しない。
- `swiftlint lint --strict --no-cache` と `xcodebuild test` の関連・回帰テストを実行。既存の実API評価は通常テストと分離する。
- 実API受入では合成会話を使用。接続先・試験モデル・最大要求数・費用枠を実行前に具体化し、未実行の経路は未検証と記録する。
