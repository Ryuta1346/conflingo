# PR6 混在言語・複数発話の回答品質修正

2026-11-10 / main d0b4379 / ユーザー「修正して」により、提示済みの回答品質2点の修正・回帰評価追加・再検証を承認済み。

## 問題と受入条件

合成12発話のUI受入で、日本語のレビュー完了確認に英語回答が1件、開始可否が不明な状態を「未定」とした回答が1件発生した。既存28ケースは各1発話で、構造・種別・根拠IDだけを自動検証するため、この品質問題を検出できなかった。

- 質問の言語で回答し、発話の言語や言語メタデータの多数派に引きずられない。
- 不明な可否と未決定の予定を区別する。明示的に未決定と発話されている場合は、その意味を保持する。
- 元発話の内容・順序・ID・言語属性を保持し、根拠IDを捏造しない。既存の日程訂正・変更案・未解決矛盾の扱いを維持する。

## 最小修正

1. Gemini要求の入力を、引用発話JSONのpartと、末尾の質問JSONのpartへ分離する。質問を長い発話列に埋めず、回答対象として最後に配置する。system指示をこの入力構造に合わせる。
2. 回答範囲を質問に絞り、unknown feasibilityをundecided scheduleへ変えない指示を明確化する。正当な未決定の表現を一律禁止しない。
3. 再現12発話と日英質問、英語多数・日本語多数、明示的未決定を含む複数発話の回帰評価を追加する。プレビューの言語属性と本文の不一致も再現条件として保持する。

モデル・応答スキーマ・Keychain・UIの変更、キーワードによる製品回答の書換え、自動再試行・追加LLM判定は含めない。通信中停止の検証は別タスクとして残す。

## TDD・検証

- HTTP境界テストで質問が最後の独立partにあり、複数発話とIDが保全される契約を先行し、現行コードでRedを確認する。
- 品質のRed証跡は2026-11-10の実UI再現記録を使う。モックのRedをモデル品質の失敗と混同しない。
- 実API評価に混在言語の複数発話セットを追加。テスト側だけで言語・禁止される未決定表現をチェックし、意味と根拠は目視も行う。分類/根拠ID/言語の成功と意味の成功を区別する。
- 初回評価は新規8ケース×3回と既存28ケースの計52要求。許可済みのGoogle Gemini・合成データ・一時ランナーのキー利用を引き継ぐ。追加修正が必要な場合は変更内容と追加要求数を明示し、同じ版の無目的な再送はしない。合成回答は目視のみに使い、成果物には本文・キーを保存しない。
- 全Swiftテスト（実APIスイート除外）、Debug/Releaseビルド、SwiftLint strict/no-cache、差分検査を実施する。

この修正の成功でも、実音声・通常起動全体・通信中停止・請求額の受入を完了扱いにしない。コミットは行わない。

根拠: [Google公式 prompting strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies)は文脈を先に、質問を末尾へ置く構造を推奨。この変更の効果は実評価で判定する。
