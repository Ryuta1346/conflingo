## 問題と再現結果

`KnowledgeIndex.search`は最大2,000文字を正規化・stop word除去し、重複を除いた語を文字順でソートして先頭32語だけ検索する。検索意図と無関係な文字順により、冒頭の検索対象が脱落する。

製品ソースを直接コンパイルした合成プローブで、`zebra`は単語だけ／全32語なら見つかるが、全33語では見つからないことを確認した。冒頭の日本語`月額`、保存資料の再読込後、リポジトリパスの`zebraTarget`も長い検索文で脱落する。繰り返し記載しても現行のSetでは救済されない。[再現記録](../validation/r5-3-query-selection-investigation.md)。

影響は資料検索画面、資料付き手動質問、共通支援の資料検索、自動提案、資料付き要約。いずれも`KnowledgeIndex.search`へ到達する。`KnowledgeStore.rankedReferences`による2,000文字分割と上位5引用の統合は別の既存処理。

## 提案する変更

**正規化後の語を初出順で重複除去し、最初の32語を選択する。**

- `words`が返す順序を保ち、stop wordを除外したうえで既出語をSetで判定する。Setを配列化して順序を決めない。
- 原語の列を先に扱い、camelCase／snake_case等の展開語が後に続く既存の`words`の出力順を維持する。正規化・日本語分割・識別子展開は変更しない。
- 検索語の選択だけを変更する。入力2,000文字、最大32語、FTSのOR条件、SQLパラメータ化／引用符エスケープ、`bm25(chunks, 0, 0, 5, 1), rowid`の順位、最大10件を維持する。
- 小さな重複除去処理を`KnowledgeIndex`内に置く。新たな検索サービス・索引・設定項目は作らない。

### 選択理由と限界

入力の先頭に示した対象が、後続語の綴りだけで押し出される問題を最小変更で直す。頻度順では反復した一般語が優先され、識別子展開による重複も頻度へ混入する。資料中の出現頻度を使う方式は追加の索引管理と品質評価が必要なため、今回採用しない。

これは意味的な重要語選択ではない。正規化・重複除去後の33語目以降は、重要でも対象外になる。末尾語の漏れや自然言語からコードへの検索品質全体を解決したとは扱わない。32語以下では従来と同じ語集合になり、検索順位の回帰も検証する。

## 対象ファイルと受入条件

製品の変更対象は`ConfLingo/Knowledge/KnowledgeIndex.swift`。公開検索APIの回帰テストを`ConfLingoTests/KnowledgeIndexTests.swift`または隣接する専用テストに追加し、保存復元・共通支援の既存テストも実行する。

| 対象 | 期待結果 |
|---|---|
| 32語超の英語 | 冒頭の`zebra`が後続の文字順の早い語に押し出されず、対応資料を検索できる |
| 32語超の日英混在 | 冒頭の`月額`を検索でき、無関係な単漢字資料を返さない |
