# 文字起こしを既定にする開始モード選択

作成日: 2026-11-12
状態: 2026-11-12 実装・検証済み。検証範囲は [検証記録](../validation/transcription-mode.md) を参照。
対象: ConfLingo / main

## 要求

MeetingとConferenceの両方で「文字起こし」を既定とし、開始前の準備画面から「リアルタイム翻訳」も選択できるようにする。

追加要件: 翻訳モードでは、原文の表示時点から訳文用の領域を確保する。文字起こしと翻訳の到着時間差による高さの変化、後続発話の移動、スクロールのガタつきを抑える。

## 変更前

- ConferenceはContentViewのAppStorage("transcriptionOnly")で選択を永続化し、未設定時はfalse（翻訳あり）。ConferenceSetupViewに「文字起こしのみ」トグルがある。
- Meetingは入力別の翻訳先を永続化し、未設定時は自分en・相手ja。翻訳先を空文字にすると翻訳をスキップする。全体の開始モード選択はない。
- 文字起こし専用の実処理、翻訳失敗時の原文保持、保存・Markdown出力は既存実装を利用できる。

## 実装した振る舞い

1. 両方の準備画面に同じ2択「文字起こし / リアルタイム翻訳」を表示し、文字起こしを初期選択とする。
2. 新しいセッション・アプリ起動時は文字起こしに戻す。過去の翻訳有効設定で翻訳が自動選択されないようにする。既存セッションの一時停止・再開や画面移動では選択を維持する。
3. 文字起こしでは翻訳先の設定を隠し、翻訳の準備・リクエストを行わない。原文の認識・表示・保存・書き出しを継続する。
4. リアルタイム翻訳では原文に加えて訳文を表示する。Conferenceは翻訳先、Meetingは自分・相手側それぞれの翻訳先を表示する。Meetingの片側だけ「翻訳なし」も維持する。
5. 翻訳先の言語の記憶と、翻訳を有効にする選択を分ける。既存の翻訳先設定は保持し、新規の翻訳先候補は現在の既定値を利用する。
6. 開始・準備・停止処理中の切替を禁止し、設定可能な停止状態で選択できるようにする。過去の原文・訳文をモード変更だけで削除しない。
7. Conferenceの高速確定は文字起こし選択時のみ利用可能とする。AIの許可・回答言語は今回のモード選択と独立させる。

## 翻訳到着時のレイアウト安定化（実装済み）

### 変更前の構造と対応

- MeetingはMeetingTranslationTextが翻訳エントリー作成後にだけ表示される。認識中は訳文欄がなく、確定時と翻訳完了時に高さが増える。通常画面と小窓の両方で、翻訳対象の入力は認識中の原文を表示する段階から訳文領域を置く。
- Conferenceは原文・翻訳の2ペインを既に確保しているが、各翻訳項目が短い待機文から複数行の訳文へ変化すると高さが変わる。2ペインの配置を維持し、翻訳単位ごとの待機領域にも高さを確保する。認識中・文の確定待ちから翻訳単位への移行で、予約領域の二重表示や不要な消滅を避ける。
- Conferenceの原文セグメントと翻訳単位は一対一ではない。既存の文単位の翻訳を維持し、見た目のために翻訳処理の分割方法を変更しない。

### 表示仕様

1. 原文は翻訳を待たず即時表示する。翻訳対象にだけ訳文ラベルと予約領域を表示し、「発話の確定待ち」「翻訳待ち」「翻訳中」を同じ領域内で切り替える。
2. 予約する高さは表示幅・文字サイズ・原文の表示量を基準に最低限の余裕を持たせる。原文確定後、同じ幅・文字サイズでは確保した高さを翻訳の進行状態に応じて縮めない。訳文到着時は予約領域内の内容を差し替える。
3. 翻訳失敗・再試行でも予約領域を残す。状態ラベルが消えることによる高さの縮小も抑える。翻訳待ちを示す架空の文は使わず、アクセシビリティでも待機状態と訳文を区別する。
4. 訳文長は事前に確定できないため、予約領域を超えた場合だけ必要な分だけ広げて全文を表示する。固定高さでの切り捨てや発話ごとの入れ子スクロールは導入しない。目的は翻訳遅延による移動の抑制であり、任意の訳文長でも完全な高さ不変を保証する仕様ではない。
5. 文字起こしモード、Meetingの片側「翻訳なし」、同一言語で翻訳をスキップする発話には、新たな空の訳文領域を設けない。Meetingでは既に取得した訳文の表示を保持する。Conferenceは文字起こしモードで原文だけを表示するが、取得済み訳文のデータは破棄しない。
6. 履歴閲覧中は翻訳到着だけで最新位置へ飛ばさない。最新追従中は下端を維持する。リサイズ・文字サイズ変更はレイアウト再計算を行う。

## 実施手順

1. 関連設計資料と日英利用ガイド、READMEの該当説明を先に更新し、変更予定と実装済みの区別を明記する。
2. 最小の共通モード定義とライフサイクルを設計し、初期値・新規開始・一時停止再開・翻訳無効時の呼び出し抑止の振る舞いテストを追加する。期待した理由で失敗することを確認する。
3. Conferenceの永続化された有効フラグをセッション内の選択に置き換える。Meetingにモード選択を加え、確定発話の翻訳処理をモードで制御する。準備画面の表示を統一する。
4. 翻訳領域の事前確保を通常Meeting・小窓・Conferenceに実装する。遅延翻訳を使い、予約範囲に収まる訳文の到着前後で行高・後続発話位置が変わらないことを先にテストする。長い訳文・失敗・再試行・認識中から確定への遷移も検証する。
5. 翻訳ありを前提とする既存テストとプレビューは翻訳を明示選択するよう調整する。不要になった設定参照と資料の矛盾を整理する。
6. SwiftLint、関連テスト、ビルドを実行し、準備画面の両モードと狭い幅の表示を確認する。保存・Markdown・停止時の最終発話の回帰を検証し、結果と未検証事項を記録する。

## 受け入れ条件

- 既存設定に翻訳有効・翻訳先言語が残っていても、新しいセッションは両方とも文字起こしが選択される。
- 文字起こしのまま開始すると翻訳モデル準備・翻訳要求が発生せず、原文を表示・保存・出力できる。
- リアルタイム翻訳を明示選択すると、指定した言語へ翻訳される。Meetingの片側無効と同一言語スキップも維持される。
- 一時停止・再開でモードと発話を保持し、新規セッションへのリセット時に文字起こしへ戻る。
- 翻訳の失敗や無効化で原文が失われず、既存の訳文も勝手に消えない。
- 翻訳対象の原文を表示した時点で訳文領域があり、翻訳処理・表示の遅延で後から欄そのものを追加しない。
- 同じ幅・文字サイズで予約範囲内の訳文が届いても、項目の高さと後続発話の位置が変わらない。失敗・再試行でも領域を保持する。
- 予約範囲を超える長い訳文を省略せず表示し、履歴閲覧中に最新へ強制移動しない。
- 通常Meeting・小窓・Conferenceで、遅延翻訳、狭い幅、大きな文字、短文・長文、認識中から確定への遷移を検証する。
- 文字起こしのみの発話には不要な訳文用の空白がない。
- リント・関連テスト・ビルド結果と画面確認の範囲を報告する。
