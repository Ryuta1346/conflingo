# リポジトリ・実装コードの資料化 — ヒアリング

2026-11-11。状態: **承認済み・ローカル実装／自動・主要UI検証完了。**

## 要望

ユーザー: 「プロダクトのリポジトリ・実装も資料対象にしたい」。
ConfLingoの会議支援AIが参照する資料を、設計文書だけでなく実装コード・テスト・設定にも広げる要望として整理する。

## 要望受付時の仕様・実装（初回調査）

- `KnowledgeIndex`を使う会議内の資料検索があり、取り込みUIはUTF-8のMarkdown/Textを対象とする。
- 20文書、1文書1 MiB・10万文字、全体50万文字。検索は日英の単語による全文検索。
- 手動質問に最大5箇所・6,000文字を付加。自動提案・終了後要約は資料を使わない。
- 資料は会議内のみ保持。会議破棄・アプリ終了で破棄する。
- フォルダ再帰取り込み、リポジトリ連携、コードの構造解析・依存関係探索は現行の承認範囲外。

根拠: [PR8計画](pr8-implementation-plan.md)、`ConfLingo/Knowledge/KnowledgeStore.swift`、`ConfLingo/Knowledge/KnowledgeDocument.swift`、`ConfLingo/Meeting/Views/MeetingKnowledgeControls.swift`。

## 確認事項

| ID | 質問 | 初期案 | 選択肢による違い |
|---|---|---|---|
| Q1 | どこからリポジトリを取り込むか | Mac上のチェックアウト済みフォルダを選ぶ | GitHub URLからの取得には認証・対象ブランチ・取得範囲の設計も必要。両方対応も選択可能 |
| Q2 | 実装資料をどの場面でAIに使わせるか | まず手動質問で使う | 会議中の自動提案や終了後要約にも使う場合は、それぞれの検索契機・送信量・品質評価を追加する |

## 回答後に具体化する設計案（未承認）

- ソース、テスト、README・設計文書、必要な設定を対象にし、取り込み前に対象を確認できるようにする。
- 依存パッケージ・生成物・バイナリ・秘密情報を含むファイルの除外規則と対象上限を設ける。
- リポジトリ名・相対パス・行番号・取り込んだ版を根拠として示す。コミット済みのコードとローカル変更を区別する。
- 「設計上の予定」「テストで期待される振る舞い」「コードで実装された処理」を区別する。実装の存在だけで、本番での有効化や動作成功を断定しない。
- 自然言語の機能質問から該当コードを探せるか評価する。拡張子の許可だけでリポジトリ理解が完成したとは扱わない。
- 保持期間は既存の会議内保持を初期案とする。会議をまたぐ永続化は別途範囲を確定する。

回答後に `~/.coding-agents/docs/conflingo/<ブランチ名>/` へ実装計画を作成し、承認後にTDDで実装する。
質問の根拠はユーザー提示AGENTS.md必須ルール1「不明確な部分がある場合は作業を中断し、ヒアリングシート（md）を作成して質問する」。実装前の承認は同ルール4に従う。

- Q2: 「終了後の要約にも利用」。手動質問に加えて終了後要約を対象とし、会議中の自動提案は初版の計画に含めない。
