# UIデザインレビュー（2026-11-15）

対象: main `8a02bc8`（PR #44マージ後）の全SwiftUI画面。指摘のみで、コードは変更していない。

## 方法と限界

- `ConfLingo/` 配下の全ビュー、`DesignTokens.swift`、[デザインシステム](design-system.md)・[情報設計](app-information-architecture.md)・[状態と操作](ux-states-and-flows.md)を読み、承認済みの方向性と実装を照合した。
- 色トークンはWCAGのコントラスト比を計算した。ブレークポイントはコード上の幅条件から算出した。
- **Linuxコンテナのためビルド・起動はしていない。** リポジトリ内のネイティブ画像（`docs/validation/pr5-b-screenshots`・`pr5-c-screenshots`、2026-11-12）はAI操作・資料・Web調査の追加前の版で、現在のMeeting Live右欄とConferenceの支援欄は画像で確認できていない。これらはコードの並び順からの判断である。
- 「要実機確認」と書いた項目は、コードだけでは断定できない。

## 結論

色・状態の文字併記・確認ダイアログの文面は設計どおりで質が高い。一方、PR6以降に追加した操作が**既存の欄へ積み増されたまま**で、承認した方向性「会議中は文字が主役」「提案が主領域」から離れている。優先して直すべきは次の4件。

1. Meeting Liveで、AI提案が設定カード2枚の下に押し出されている（D01）。
2. Conferenceの翻訳表示が、設計基準寸法の1280pt幅で縦積みになる（D02）。
3. 「会議を終了」が確認なしで不可逆（D03）。
4. 送信範囲の説明を含む補助文が10ptで描画される（D04）。

## 指摘一覧

重要度: **高**=主要タスクを妨げる／誤操作で失う、**中**=一貫性・理解を損なう、**低**=仕上げ。

### 高

**D01 Meeting Live: 提案より上に設定カードが2枚ある**
`MeetingWorkspaceView.swift:139-187`。右欄は 見出し「いま、役立つ提案」→ `MeetingAIControls`（:144）→ `MeetingKnowledgeControls`（:151、既定で展開 `MeetingKnowledgeControls.swift:7`）→ 候補 → 提案カード の順。AI操作カードは回答言語・許可トグル3つ・説明文4段・質問欄・Web調査・状態表示を含み、資料カードは追加ボタン・一覧・検索・認識方式・用語抽出・許可を含む。見出しの直下に提案がなく、新しい提案は2枚の下に追加されるため、会議中にスクロールしないと読めない。新着の通知もない。モック（`mockups/meeting-light.png`）は提案→1行の質問欄→状態は下部バーだった。
提案: 右欄を「提案一覧＋1行の質問欄」に戻す。許可・回答言語・LLM設定・送信内容の説明は、状態チップから開くポップオーバーかシートへ移す。資料カードはLiveでは既定で閉じる。Conferenceの支援欄（`ConferenceAssistanceView.swift`、トグル4つが回答より上）も同じ構造に揃える。

**D02 Conference翻訳表示: 1185〜1345pt幅で字幕が縦積みになる**
`ContentView.swift:252` はコンテンツ幅1000以上で支援欄（340pt）を出し、`ConferenceLiveView.swift:16` は自身の幅820未満で原文・訳文を縦に積む。サイドバー184ptを引くと、ウィンドウ幅1185〜1345ptでは「支援欄あり＋字幕縦積み」になる。デザインシステムの基準寸法1280×800がこの範囲に入る。既定サイズ1180ptは横並びで、5pt広げると縦積みに変わる。支援欄を閉じる操作もない。
同じ原因で幅の変化が単調でない: 900〜1004ptは縦積み、820〜899pt（上部ナビへ切替）は横並び、820pt未満は再び縦積み。Meetingも900〜1016ptが縦、832〜899ptが横、832pt未満が縦（`MeetingWorkspaceView.swift:29`、`AppShellView.swift:11`）。
提案: 字幕の2列を優先し、支援欄は字幕幅820を保てる場合（ウィンドウ1346pt以上）だけ自動表示、それ以外は開閉ボタンで重ねる。シェルの切替幅と各画面の切替幅を1つの基準（コンテンツ幅）で決める。

**D03 「会議を終了」が確認なしで不可逆**
`MeetingTransport.swift:49-51`。「一時停止」と「会議を終了」が同じ大きさ・同じ様式で隣接する。終了すると振り返りへ移り、再開できない（`MeetingWorkspace.swift:296` が `page != .review` で弾く）。押し間違えると以降の発話を記録できない。Conferenceは停止後に再開できるため、モード間で結果の重さが違う。
提案: 終了に確認ダイアログを付けるか、振り返りから「会議を再開」できるようにする。2つのボタンは間隔を空け、終了は右端に離す。

**D04 補助文が10ptで、送信範囲の説明が読みにくい**
`.font(.caption)` が152箇所、`.caption2` が4箇所。macOSの `.caption` は10ptで、デザインシステムの「補助12px」を下回る。「確定発話を最大30件送ります」「資料の抜粋を最大5箇所・6,000文字送ります」など、同意の判断材料になる文がこの大きさで、補助色（ライトで4.9:1）になっている。字幕の文字サイズ設定でも拡大されない。
提案: `DesignTokens` に本文・補助・注記の文字様式を定義し、補助は12pt以上にする。送信範囲の説明は本文色にする。

### 中

**D05 候補カードの状態ラベルが、確認済みでも警告色と「？」**
`MeetingWorkspaceView.swift:228`。`StatusLabel` の色と記号が固定で、「確認済み」「却下」「中断」「生成中・未検証」のすべてが琥珀色＋疑問符になる。デザインシステムは positive を「確認済み」に割り当てている。
提案: 状態ごとに色と記号を切り替える（確認済み=positive＋チェック、却下=secondary＋×、生成中=secondary＋進行）。

**D06 ボタンの階層がなく、全ボタンが青い**
`AppShellView.swift:27` の `.tint(accent)` により、通常ボタンもすべて青文字・青地で描画される（`pr5-b-screenshots/conference-wide-light.jpg` で A−／A＋／最前面／書き出す／字幕の設定／字幕を消去 がすべて青）。デザインシステムは「青を主要操作と選択に限定」と定めている。`DesignTokens.swift` にボタン様式の定義がなく、各所で `.borderedProminent`（16箇所）・既定・`.plain` を個別に選んでいる。
破壊操作の表現も揃っていない: 保存セッションの「削除」（`SavedSessionView.swift:38`、`SessionsView.swift:81`）と「字幕を消去」（`ConferenceLiveView.swift:55`）は通常ボタン、資料ライブラリの「削除」は `role: .destructive`、「停止を再試行」はMeetingが強調ボタン（`MeetingTransport.swift:40`）でConferenceが危険色（`ControlBar.swift`）。根拠リンク（「00:00:12・内部音声の発話を見る」）も通常ボタンと同じ見た目で、1枚のカードに操作が並びすぎて見える。
提案: 主要／通常／破壊／リンクの4様式をデザインシステムに定義して置き換える。通常ボタンは無彩色にする。

**D07 エラーと状態メッセージの表現が3通りある**
`SessionErrorBanner`（危険色＋記号）のほかに、警告色の文字だけ（`KnowledgeLibraryView.swift:22` ほか多数）と、色なしの10pt文字（`MeetingSaveControls.swift:27`、`ConferenceAssistanceView.swift:23`）がある。失敗が警告色（デザインシステムでは「未確認・要対応」）で出る箇所が多く、記号がないため色だけに頼っている。成功と失敗が同じ見た目の箇所もある。
また `error.localizedDescription` を画面へ直接出す箇所があり（`MeetingTranslationPreparation.swift:41` など）、日本語UIに英語のシステム文言が混ざる（`r6-meeting-translation/terms-420-failed.png` の「The file couldn't be opened.」）。
提案: 情報／成功／警告／失敗を持つ行内メッセージ部品を1つ作り、記号を必ず付ける。システム由来の文言は「詳細」に畳む。

**D08 Conferenceの「資料・AI支援」シートに9機能が入っている**
`ConferenceKnowledgeView.swift`。保存、書き出し、資料、認識方式、用語抽出、発話＋資料の支援、資料だけの質問、LLM設定、補正が1本のスクロールに並ぶ。モーダルなので使用中は字幕が読めない。シートは最大3段重なる（このシート→LLM設定→接続編集）。保存と書き出しは字幕画面・上部バーと重複する。支援欄はサイドとシートで別々の入力状態を持ち（`ConferenceAssistanceView.swift:5`）、書きかけの質問が引き継がれない。
提案: 実行中に使うもの（質問・提案）はサイド欄だけに置き、準備で使うもの（資料・用語・認識方式）は準備画面へ移す。補正は字幕の該当行から開く。保存・書き出しの重複は削る。

**D09 Conference字幕の上に、実行中は使えない保存ブロックが常設**
`ContentView.swift:238`。「このMacに保存」ボタン＋状態＋説明文が字幕の上を占める。保存は停止後だけ可能（`SessionCapture.swift:20`）で、実行中は無効のまま残る。情報設計で挙げた「720×560で字幕の高さを圧迫」を再び招いている。
提案: 保存は上部バーの「書き出す」の隣へ移し、状態はボタン横の短い表示にする。

**D10 AI許可のトグルが多く、配置と文言がモード間で違う**
Meetingは6つ（送信、自動提案、自動提案の資料、手動質問の資料、要約時の資料、Web調査）、Conferenceは7つ。細かく分ける方針は妥当だが、同じ概念の置き場所と文言が違う。発話の送信は「確定発話と質問文を〇〇へ送信することを許可」（Meeting）と「発話を使ったAI支援を許可」（Conference）。手動質問の資料許可はMeetingでは資料カード内、ConferenceではAI支援内。親が切のとき子が無効になる関係も、字下げなどで示していない。
提案: 「何を・どこへ・いつ送るか」を1枚の表にまとめた送信範囲パネルを両モード共通で使う。

**D11 Macの標準操作に乗っていない**
- メニューバーへの追加は「Meetingの小窓を表示」だけ（`ConfLingoApp.swift:31`）。開始／停止、文字の拡大縮小、最前面がメニューになく、ショートカットは設定画面の説明文でしか分からない。
- `Settings` シーンがなく、⌘, で設定を開けない。
- `.keyboardShortcut(.defaultAction)` が0件で、シートの主操作をReturnで実行できない。
- Meetingには開始・一時停止・終了のショートカットがない（⌘RはConferenceのみ）。
- 拡大は `"+"` で登録（`ContentView.swift:293`）。US配列ではShiftが必要になる可能性がある。要実機確認。

**D12 Meeting準備のフォームがConference準備と揃っていない**
`MeetingWorkspaceView.swift:68-122`。
- 会議名はプレースホルダだけで常設ラベルがない（:74）。Conferenceは上にラベルを置く。
- Pickerを縦に並べただけで、ラベル幅が揃わない（`pr5-c-screenshots/meeting-preparation.jpg`）。
- 音声入力で「マイクのみ」を選んでも、内部音声の言語と翻訳先を表示する。
- 認識言語が日本語／Englishの2択固定（:200）。Conferenceは対応言語の一覧を出す。
- 「会議を開始」が無効の理由（同意チェック未了など）を示さない。
- 権限の状態が10ptの文字だけで、未許可のときにシステム設定を開く操作がない（:104）。

**D13 文字サイズ設定の適用範囲が揃っていない**
提案カード・要約・保存記録は設定値で拡大するが、質問の回答とWeb調査の回答は既定サイズのまま（`WebResearchView.swift:27`）、そこから開く資料引用は16pt固定（:41）。逆に資料ライブラリは一覧の題名まで拡大する（`KnowledgeLibraryView.swift:48`）。
提案: 「読む本文」（字幕・回答・引用・資料本文）だけに適用し、一覧の題名や操作部品には適用しない。

**D14 名称の揺れ**
- 画面名: サイドバー「保存したセッション」／上部バー「Sessions」（`ContentView.swift:280`）／狭幅ナビ「保存」（`AppShellView.swift:36`、保存操作に見える）／一覧の小見出し「ライブラリ」（`SessionsView.swift:18`、資料ライブラリと紛れる）。
- 入力: 内部音声／Macの内部音声／システム音声、マイク／マイク・外部入力。
- 操作: 「Ask AI」（Meeting）と「質問する」（Conference）、「書き出す」と「Markdownを書き出す」。
- AI出力の注記: 要確認／未確認／生成中・未検証／根拠なし・要確認。
- `Meeting / General`（`MeetingWorkspaceView.swift:127`）は未提供のプリセット構想の名残で、利用者には意味が通じない。

### 低

角丸は6・7・8・12が混在（定義は操作7・パネル12）。余白は3・5・6・10・14・18・20・28を多用（定義は4/8/12/16/24/32）。固定文字サイズ12・13・17・24・25と意味様式が混在。補助色は `DesignTokens.secondary` が103箇所、システムの `.secondary` が19箇所。サイドバー幅184（設計172）、小窓420×430（設計440×350）。

**D16 シートの作法が揃っていない**
「閉じる」の位置が右上・右下・左下・中央下の4通り。背景も canvas 指定と既定が混在。LLM設定シートはMeetingが幅680・余白24、Conferenceが最小560×420・既定余白。

**D17 会話の流れ**
確定発話ごとに「この発話をWebで調べる」ボタンが付き、行数が増える（`MeetingTranscriptView.swift:40`）。ホバーか右クリックへ移したい。入力元の区別は10ptの文字だけ。ヘッダ右の「入力元ごとに表示」と常設フッター（:94）は同じ内容。

**D18 Home**
Conferenceは大きい記号＋強調ボタン、Meetingは行内記号＋通常ボタンで、2つの入口のカード構造が違う。副題「聞きながら、原文と翻訳を読む。」は既定が文字起こしになった現在の仕様と合わない。

**D19 状態表示**
トランスポートに経過時間がない（部品契約にはある）。選んでいない入力も「停止」と表示する。Meetingの取得中表示は下部の10pt文字だけで、Conferenceのチップ表示より弱い。状態変化のVoiceOver通知（live region）は0件。

**D20 保存したセッションと資料ライブラリ**
同じ一覧系の画面で、見出し部品・最大幅・再読込ボタンの記号・行の操作配置が違う。行全体は押せず、「開く」ボタンだけが反応する。資料詳細に保存版ID・ハッシュ・snapshot IDが主要情報として出る。

## 維持したい点

- 認識中・翻訳待ち・翻訳失敗を色だけでなく文字で併記している。
- 履歴を読んでいる間は自動スクロールを止め、「最新へ」で戻す動作が両モードで共通。
- 確認ダイアログが「何が消え、何が残るか」を具体的に書いている。
- `ViewThatFits` による狭幅対応と、アクセシビリティラベルの付与が行き届いている。

## 進め方の案
