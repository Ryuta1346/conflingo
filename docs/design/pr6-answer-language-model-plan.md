## A. 回答言語の事前設定（実装案）

- 初期対応は日本語・English、初期値は日本語。設定画面とMeetingの準備画面から同じ設定を変更でき、UserDefaultsへ保存して再起動後も保持する。
- 音声認識言語・字幕翻訳先とは独立した「AIの回答言語」。質問・発話が別言語でも選択言語で回答する。手動質問と自動提案の両方に適用する。
- `InsightRequest`が要求作成時の言語を保持し、送信JSONにも明示する。送信中に設定を変更してもその要求の言語は変えず、次の要求から適用する。過去の回答を翻訳し直さない。
- 既存の「質問の言語で回答」の指示・例文を、選択した回答言語が優先される契約に整理する。利用者の質問本文へ指示文を追記する方式は使わない。
- プレビューやテストでは注入したUserDefaultsを使い、本番の保存値を変更しない。未知の保存値は日本語へ戻す。
- 対象: ContentView / SettingsView / MeetingWorkspace / MeetingAIControls / InsightCoordinator / InsightRequest / GeminiInsightClient、対応するテスト・プレビュー。言語の選択肢と要求契約を表す最小の型を追加する。
- TDD: 保存と復元、字幕設定との独立、手動/自動への伝搬、設定変更中の要求の固定、HTTP本文に選択言語が保たれることを検証。全ローカルテスト・Debug/Release・lint、非録音UIの設定操作を確認。

## B. モデル比較（承認後、最大72要求）

Aの言語設定を全条件に同じように適用し、プロンプト・入力・出力スキーマを固定する。モデル/推論設定以外を同時に変えない。言語設定を変更したため、前回62件と今回の差をモデル効果とは扱わない。

**12ケース × 2回 × 3条件＝最大72要求**。3条件は上表。以下10ケースに言語設定の対照2件を加える。

1. long-en-question（広い質問、独立した事実）
2. mixed-en-feasibility（反復で因果を補った失敗）
3. ja-conflict（対象不明の曜日発話）
4. en-conflict（食い違い自体は明示）
5–10. dependency-unstated / dependency-explicit / subject-unstated / subject-explicit / update-expected / update-scheduled
11. 日本語の質問・日本語の根拠、回答言語English（未確定金額）
12. 英語の質問・英語の根拠、回答言語日本語（未確定金額）

- ケース・反復ごとに3条件を順番に実行し、条件順は循環させる。成功するまで再送しない。アクセス拒否・timeout・打切りも失敗として数える。利用不可モデルへの代替切替なし。
- 評価用のmaxOutputTokensは全条件8192で統一。現在の1024に固定した製品経路と同一とは扱わない。回答本文8000文字・受信サイズ等の既存制限、30秒の要求timeoutは保持する。
- 測定: 内容の正確さ、指定言語一致、無効ID、初回本文までの時間・完了時間、入力/出力/思考token、推定費用。意味は全件を固定根拠と照合する。
- 一般語eventは予定の対象を特定していないため単独での自動不合格にはせず、具体的な会議・公開・未提示の予定の成立まで補う場合を不合格とする。以前の要確認5件はそのまま残し、この比較のルーブリックとして事前固定する。
- 根拠にない因果・曖昧な曜日への矛盾断定が残れば当該ケースは不合格。明示された依存・変更・予定を削って無難な回答にすることも不合格。
- 同じ意味精度なら費用・遅延が低い候補を優先。局所比較の成功だけでPR6全体を合格にせず、採用候補の既存全ケース・UI回帰を後続で計画する。

Google Geminiへ合成データだけを送信、既存認証済みホスト/キーを利用、キー変更・録音なし。本文やキーを作業ファイルへ保存せず、判定・ハッシュ・使用量を記録する。前回62要求枠は使用済みで、この72件は別枠。

費用の目安: 各条件24件、入力約3000token/件、思考込み出力上限8192token/件を全件使う計算で合計約US$1.42（現行Standard単価、税等を除外）。入力token数・請求条件により変わるため請求額の保証ではない。推定累積US$2に達したら以後の送信を停止し、上限到達時は未実施を残す。追加のLLM判定・外部検索ツールは使わない。
