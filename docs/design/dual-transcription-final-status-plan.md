# 2入力文字起こしの停止後表示を修正する計画

2026-11-10。状態: ユーザー「進めて」により承認済み。表示修正・合成UI再現/回帰・テスト/ビルド/lint完了。実音声の再取得は未実施。正本: `~/.coding-agents/docs/conflingo/main/dual-transcription-final-status-plan.md`。

## 問題と到達点

[実音声試験](../validation/real-audio-resume.md)で、両入力停止後も内部音声9文のうち8文に「認識中」が残った。AXだけでなく画面でも再現。日本語4文は確定し、両入力の停止は完了した。認識結果の最終化不足か、SwiftUIの表示更新かは未確定。停止時に未確定データを一律finalへ書き換える対応はしない。

停止後、取得済みfinalは正しい本文・入力元・確定状態で一度だけ表示され、partialが古い行として残らないことを目標にする。取得できなかったfinalを捏造せず、終了失敗は既存エラー経路で伝える。

## 対応手順

1. 資料に観測事実と未確定部分を保ったまま、同じIDがpartialからfinalへ移る合成イベント列で再現する。必要な診断はID・origin・isFinal・revision・時刻・件数に限定し、本文や音声をログ保存しない。
2. TDDで回帰を追加する。複数文のpartial→final、入力間の交互到着、停止時final排出、partial消去の契約を検証する。ストアが正しくても表示が残る場合は、合成イベントによるUI再現を修正前後の根拠にする。
3. 原因に応じて最小修正する。対象候補は `DualTranscriptionProbeView` の行の識別・更新、`TranscriptEventNormalizer`、`MeetingSessionStore`、`DualTranscriptionController` と認識終了処理。表示が原因なら、同じ発話を単一のForEachで更新するなど局所的な修正に留める。製品全体のモデル・AI設定は変更しない。
4. 関連テスト、全体テスト、SwiftLint、Debug/Releaseビルドを実行。合成UIで各文の確定表示・重複なし・停止後変化なしを確認し、必要に応じて今回と同じ短時間の実入力で再確認する。最後に短い停止→再開で旧字幕の混入を確認する。

## 受入条件

- 内部音声9文とマイク4文の内容・入力元・数値を保持する。
- final受信後に旧partial表示が残らず、同じ発話が重複しない。
- 両入力停止と認識終了を確認後、finalだけを表示する。終了失敗時は正しくエラーを示す。
- 停止後の字幕追加がなく、再開しても古い結果を新しい入力へ混ぜない。
- API要求0、キー変更なし、音声・認識本文のログ保存なし、コミットなし。

## ビルドと権限

認証済み元ビルドは上書き・再署名しない。修正検証用を別出力先へビルドする。OSが新しい権限や本人認証を要求した場合に限り、その場で利用者へ操作を依頼する。実音声は利用者が読める状態を確認して短時間で実施し、通常Meeting全状態・各会議サービス・60分耐久の合格とは分ける。
