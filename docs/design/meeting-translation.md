## 目的・提案仕様

MeetingでマイクとMac内部音声の確定発話を自動翻訳し、原文と訳文を読めるようにする。Conferenceと同じApple Translation.frameworkを使用し、翻訳にクラウドAIの許可・APIキーを要求しない。必要な言語モデルの初回ダウンロードはOSの確認に従う。

1. 準備画面に入力別の「翻訳先」を追加する。既定は文字起こしで、「リアルタイム翻訳」を選んだ場合に翻訳先を表示する。翻訳先の初期候補はマイク: 日本語→英語、内部音声: 英語→日本語。各入力を個別に「翻訳なし」にできる。翻訳先はOSが対応する言語から選択し、実際の言語ペアの可否を確認する。認識言語の選択肢は既存仕様を維持する。
2. 原文を残し、各確定発話の下に訳文と翻訳先言語を表示する。認識途中のpartialは翻訳しない。同じ言語の組み合わせでは翻訳を呼び出さず、原文を表示する。
3. 設定は準備画面の停止中だけ変更できる。設定変更は次の開始以降の発話に適用し、既存の原文・訳文・翻訳先を保持する。翻訳先の選択は次の会議でも再利用する。
4. 翻訳中・失敗を表示する。モデル準備の拒否、非対応ペア、翻訳失敗が起きても文字起こしともう一方の入力の翻訳を継続する。失敗した翻訳は明示操作で再試行できる。
5. 一時停止・会議終了では音声入力を止め、取得済み確定発話の翻訳を完了させる。保存・書き出し時はその時点の完成訳を含め、後から訳文が完成した場合は既存の変更検出で再保存が必要なことを示す。新しい会議への切替では旧処理を無効にする。
6. 通常画面と小窓に原文・訳文を表示する。小窓への切替や他画面への移動で翻訳が止まったり、二重実行されたりしない。
7. 保存したセッションの閲覧とMarkdown書き出しに訳文・言語を含める。既存の保存済みセッションは保持し、訳文なしで読めるようにする。
8. 翻訳先と「AIの回答言語」は別設定と明示する。AI回答・要約・根拠参照は引き続き元の確定発話を使用し、翻訳処理からAI送信を追加しない。

初期の言語ペアを含め、上記はユーザーが承認した仕様。実装・検証結果は[検証記録](../validation/meeting-translation.md)を参照。

## 現行実装と変更方針

- `ContentView.swift`: Conferenceの`.translationTask`とモデル準備、Meetingの常駐Viewを保持。Meeting用の翻訳実行を画面切替に依存しない場所に追加し、OSセッションを許可された寿命内で扱う。
- `TranslationCoordinator.swift`: ID重複排除とAsyncStreamを扱う。小さく再利用できる箇所を使い、Conference全体の作り替えは行わない。
- `MeetingWorkspace.swift` / `MeetingSessionStore.swift`: 現行は原文イベントのみ。入力別翻訳設定と、session ID・発話ID・原文言語・翻訳先・処理世代を識別するMeeting用翻訳状態を追加する。原文イベントそのものと訳文を分離する。
- `DualTranscriptionController.swift` / `TranscriptEventHub.swift`: 2入力の確定発話を既存経路から購読する。非同期処理の開始前に購読を接続し、停止時の最後の確定発話も取りこぼさない。翻訳待ちで録音・認識をブロックしない。
- 翻訳処理は入力別に管理し、同時到着・古い結果・再開・再試行を制御する。UI再構成時には未完了の処理を再接続でき、完了済み発話を再翻訳しない。
- `MeetingWorkspaceView.swift` / `MeetingTranscriptView.swift` / `MeetingFloatingPanel.swift`: 入力別設定、原文と訳文、状態・再試行操作、小窓の直近発話表示を追加する。
- `MeetingMarkdownExporter.swift` / `SessionCapture.swift` / `SessionSnapshot.swift` / `SavedSessionView.swift`: 完成訳を保存・表示・書き出しへ接続する。任意フィールドを追加し、旧JSONの欠落フィールドを許容する。保存データの発話参照・重複・セッション整合を検証する。データ削除や一括移行は行わない。
- フレームワーク固有の処理は薄くまとめ、翻訳クライアントをfakeへ差し替えて認識・OS許可・ダウンロードなしで振る舞いを検証する。既存Conference翻訳の回帰も確認する。

1. 承認後、`docs/design/meeting-translation.md`に仕様・非同期ライフサイクル・保存仕様・受入条件を記載する。`plan.md`、READMEの日英版、`docs/usage.ja.md`のMeeting関連記述を整合させ、実装予定と完了済みを区別する。既存ガイドの保存・書き出し未対応という古い記述も現行実装に合わせて修正する。
2. 下記の公開動作をfake翻訳クライアントでテストし、期待する理由でRedを確認する。最小実装でGreenへ進み、必要な整理を行う。
3. 表示・設定・保存・Markdownまで接続し、UIの合成プレビューで確認する。試験用プレビューは本番設定・権限・保存領域を共有しない。
4. 関連テスト、全既存テスト、SwiftLint、Debug/Releaseビルドを実行する。変更と資料の整合、不要コード、未検証事項を確認し、`docs/validation/meeting-translation.md`に結果を残す。
5. 合格したReleaseを`/Applications/ConfLingo.app`へ更新する。実行中の会議や未保存データを破棄しない。更新前のアプリを退避し、起動先とバイナリ一致を検証する。アドホック署名変更でOSが再許可を求めた場合は、今回の既知事象を踏まえて案内する。権限を予防的にリセットしない。

## 受入条件・テスト項目

- 自分の日本語→英語と、相手側の英語→日本語が独立して対応する発話に表示される。
- 片系オフ、両系オフ、原語と翻訳先が同一、非対応ペアを正しく扱う。
- partial・重複イベントを翻訳しない。同時到着、遅い結果、順不同の完了でも別の発話に混ざらない。
- 準備拒否・翻訳失敗・再試行中も文字起こしを継続し、再試行で完成済みの訳文を壊さない。
- 一時停止→再開、終了時の最終発話、会議破棄→新規開始、設定変更で古い結果が混入しない。
- 画面移動・小窓表示/非表示で翻訳セッションを重複起動せず、取得済み発話の翻訳が継続する。
- 原文を保存したまま訳文を併記し、保存・再起動後の閲覧・Markdown再出力まで一致する。
- 既存の訳文なし保存JSONを読み込める。存在しない発話への訳文や重複した訳文は不正として扱う。
- 訳文の後着により、保存済み/書き出し済み表示が正しく更新される。
- 翻訳のためのクラウドAI呼び出しが発生せず、AIの根拠IDと原文を維持する。
- Conferenceの翻訳、音声の排他制御、既存のAI・要約・保存機能に回帰がない。
- 主画面・小窓・保存画面で長い訳文、狭い幅、文字サイズ拡大、キーボード操作を確認する。

## 検証の境界

自動テスト・合成UI確認と、Apple実翻訳モデルの品質・実音声での認識品質は別に報告する。初回モデルのダウンロード確認や音声権限はユーザーの操作を尊重し、未実施なら実機確認済みとはしない。Zoom/Meetそれぞれの長時間受入はこの変更のみで完了扱いにしない。

## 実装上の具体化

確定発話の取りこぼしを防ぐため、MeetingSessionStoreが確定発話を受理した直後の同期コールバックで翻訳へ渡す。追加のHub購読は作らない。モデル準備は常駐ViewのtranslationTaskで行い、準備後の翻訳はmacOS 26のTranslationSession(installedSource:target:)を使う。翻訳処理はUI表示状態から独立し、入力が同じ言語ペアなら同じ直列キューで処理する。言語設定を変えても既存発話の翻訳先は保持する。

参考: [Apple TranslationSession](https://developer.apple.com/documentation/Translation/TranslationSession)、[installedSource](https://developer.apple.com/documentation/translation/translationsession/init(installedsource:target:))。
