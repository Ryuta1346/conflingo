## 修正内容

1. 音声エラーの表示を `UserMessage` で保持する。権限拒否、入力占有、字幕overflow、機器変更などアプリが定義した日本語の影響・復帰案内は本文に残す。未知のOS診断は日本語の概要と分離し、詳細へ格納する。Conference・Meeting準備／Live・小窓へ同じモデルを渡す。停止失敗の再試行・開始／リセット時のクリアは維持する。
2. 複数ファイルの取込結果を `KnowledgeStore` が保持する。既存の逐次取込、呼び出し元の取込処理、編集可否、世代判定、許可解除を維持し、資料操作の無効化・取消・リセット時に集計結果を消去する。画面は同じ状態所有元から現在の取込結果または最新通知を表示する。

## 実施順・受け入れ条件

1. この計画と関連設計資料を先に更新する。
2. fake入力と一時資料を使い、権限拒否・字幕欠損警告が詳細を開かず読めるテスト、未知の診断が初期非表示のテストを先行追加する。
3. 複数ファイル取込後のライブラリ追加／リポジトリ取り外しで最新通知へ置き換わるテスト、複数ファイルの成功・失敗が残るテストを先行追加する。
4. Redの理由を記録し、最小実装でGreenにする。新しい状態APIを参照するテストのコンパイル失敗と実行時失敗を区別する。
5. 関連テスト、全非liveテスト、SwiftLint、差分検査を実行する。実API、実音声、VoiceOverの手動操作は行わない。
6. 結果を検証資料へ反映し、不要な画面ローカル状態と古い完了状況を整理する。コミット・pushは行わない。

保存形式・音声の取得／停止契約・資料送信の許可条件は今回の変更対象外。
