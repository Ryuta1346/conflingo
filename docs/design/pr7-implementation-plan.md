## 目的と承認境界

Meeting終了後、利用者が根拠を確認して決定・アクション候補を確認／却下し、要約と発話をMarkdownに書き出せるようにする。AI生成だけでは決定・担当・期限を確定しない。

- 「さきにPR7を進める」により、修正版の実音声受入を持ち越してPR7の計画を先行する。PR6・Gate A/B/C/U/Dを完了に変更しない。
- [ヒアリング](pr7-hearing.md)のQ1/Q2は提案どおり承認。「Markdown書き出しまで・終了後の手動AI要約」を実装し、Sessionsは後続へ持ち越す。
- 承認後は資料更新→TDD→最小実装→lint・テスト・非録音UI受入の順で進める。実音声、実APIによる有料評価、コミット・push・PR作成は今回の計画承認だけでは実行しない。
- 実API評価は別途、合成fixture・要求数・費用上限を具体化して承認する。既存評価枠の流用はしない。

## 承認済み対象範囲

1. 決定／アクション候補の一覧と、未確認・確認済み・却下の状態管理。
2. 根拠発話への移動、確認／却下／未確認へ戻す操作。LiveとReviewで同じ状態を表示。
3. 会議終了後の明示操作によるAI要約。対象範囲・言語・未検証状態・中断／失敗を表示。
4. ReviewからMarkdownを明示書き出し。会議情報、要約、状態別候補、確定発話を出力する。
5. 空状態・失敗・キーボード・拡大表示の非録音プレビューと回帰テスト。

本案に含めないもの: アプリ内Sessionsの永続保存／検索／削除、RAG、専門モード、候補本文の編集・担当者選択・期限入力・タスク管理連携、AIによる自動確定、自動保存、モデル変更、音声認識の変更。既存MVPのSessions要件を削除するのではなく、後続の別計画へ残す。

## 振る舞いの契約

### 候補

- `MeetingCandidate`（名称案）は会議ID、元カードID、種類、本文、根拠発話ID、利用者の確認状態を持つ。初期状態は必ず未確認。
- AIの正常完了時に候補を1回取り込む。生成途中・中断カードは確定候補にしない。同じIDの再通知で重複させない。意味が似た別候補を勝手に統合しない。
- 100件のカード表示上限で候補や確認状態を消さない。候補は当該会議の破棄までメモリ保持し、会議をまたいで引き継がない。
- 確認可能なのは正常完了・空でない本文・有効な根拠を持つ候補だけ。根拠なし／無効IDを含むものは要確認のまま説明を表示し、却下は可能にする。
- 確認済み・却下から未確認へ戻せる。戻すことは候補本文・発話の削除ではない。利用者の確認はAIの正しさや会議参加者全員の合意を自動保証しない旨を表示する。
- 後のAI出力が以前の確認を上書きしない。変更・訂正は別の未確認候補として残し、利用者が見直せる。
- 根拠クリックでは元の発話時刻・入力元へ移動する。マイク／内部音声を人物名に変換しない。担当者・期限は推測で追加しない。

### 終了後の手動AI要約

- 音声停止成功後のReviewでのみ開始可能。会議終了やReview表示だけでは通信しない。
- 会議中AIの許可と分けて、Geminiへの送信対象（許可前を含む確定発話）、選択回答言語、区間数／予定要求数を表示し、「この内容を送って要約する」で開始する。会議中AIや音声入力は再開しない。
- 確定発話を時系列で30件・12,000文字以下の区間に分ける。各区間は既存`InsightClient`の要求上限を守り、切り捨てがないことを検査する。単一発話が上限を超える場合は黙って除外せず、生成不可の理由を表示する。
- 初期上限は1操作20区間。超過時は送信前に説明し、会議全体の要約を装って末尾だけ送らない。上限は実装計画の承認対象。
- 複数区間では区間別の要約を順に表示し、時刻と根拠を付ける。後続の訂正があり得るため、区間の記述を会議全体の最終合意と呼ばない。追加の統合LLM要求は行わない。
- 確認済み決定・アクションの一覧は利用者の確認状態からローカル生成する。要約がこれらの状態を変更することはない。
- 回答言語と発話スナップショットを開始時に固定。結果はAI生成・未確認と表示し、存在しない根拠・空回答・異常終端は成功扱いしない。
- 停止、キー変更、会議破棄、会議ID変更、アプリ終了で取消。停止後の遅延応答は採用せず、後続区間を送信しない。画面から離れる場合も要約を止め、既存会議は保持する。
- 各要約要求は[承認済み期限修正](pr7-summary-deadline-plan.md)で60秒へ変更した（2026-11-11、372テスト・lint・Debug/Release成功、実API8/8区間合格）。出力上限を維持し、直列実行・自動再送なし。二重クリックで多重送信しない。進捗・部分成功・失敗を区別し、未完了の要約を完成扱いしない。
- 再生成を取り消す／失敗する場合は直前の完成要約を保持する。新しい結果が全区間成功した時だけ完成版を置換する。

### Markdown出力

- レビュー後の修正契約は[PR7レビュー修正計画](pr7-review-fixes.md)を参照。実入力開始日時、重複発話を含む要約区間、保存後の変更判定と書き出し性能を対象とする。

- 初期版は停止成功後のReviewのみ。書き出し時点のスナップショットから、選択した場所にUTF-8で原子的に保存する。
- 内容: 会議名・開始日時（取得不能なら明示）・入力言語、完成したAI要約（存在する場合／AI生成・未確認の表示付き）、確認済み決定／アクション、未確認候補、却下候補、確定発話全文。
- 各候補と要約に根拠の時刻・入力元・同一Markdown内参照を含める。生成中の断片を完成要約に含めず、AI一般回答カードは議事結果へ混入させない。
- 未確認・却下を確認済み一覧に混ぜない。担当・期限が本文にない場合は追加しない。発話のpartialは除外する。
- AI未許可・キー未登録・オフラインでも、候補一覧と確定発話を書き出せる。書き出し操作でAI要求しない。
- 保存ダイアログのキャンセルは無変更、失敗は画面に理由を示しデータを保持。成功時だけ「書き出しました」を表示し、アプリ内保存済みとは表示しない。後から候補を変更した場合は前回出力と同一とは扱わない。
- ファイル名にパス区切りや改行を使用しない。本文のMarkdown記号やHTMLが見出し・確認状態を偽装しないよう適切にエスケープする。会議本文をログへ出さない。
- 新規会議／破棄の確認は維持。外部Markdownを書き出しても、アプリ内の会議が再読込可能になったとは扱わない。
