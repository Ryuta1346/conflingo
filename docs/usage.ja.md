# ConfLingo 使い方ガイド

[English](usage.md) | **日本語**

MeetingとConferenceは、新しいセッションでは「文字起こし」が選択されています。開始前に「リアルタイム翻訳」を選ぶと原文に訳文を追加できます。Conferenceの認識言語は英語が初期値で、翻訳を選んだ場合の翻訳先候補は日本語です。認識言語・翻訳先は、このMacで対応する言語から選択できます。macOS 26以降・Apple Siliconが必要です。

## 両モード共通の入力とAI支援

Conferenceは字幕と発話理解を中心に、Meetingは会話と論点の確認を中心に表示します。どちらでも資料登録、発話＋資料への質問、自動提案、Web調査を使えます。対面・オンラインという開催形式で機能は変わりません。

準備画面の「音声入力」で、マイク・外部入力機器、システム音声、両方を選びます。外部マイクや音声機器はmacOSのサウンド設定で入力先に指定してください。システム音声はZoom等を含むMacの再生音を取り込み、特定のアプリだけには限定しません。入力変更は停止中に行い、再開後の音声に適用します。

1. 「資料を追加」または「ライブラリから選択」で資料を登録します。
2. Conferenceでは「資料・AI支援」の「資料と発話から支援」、MeetingではAI支援の送信先を確認して許可します。資料も参照する場合は手動質問の資料利用もオンにします。
3. 質問すると、直近の確定発話（最大30件・12,000文字）と関連資料（最大5箇所・6,000文字）を使います。音声開始前は資料だけでも質問できます。
4. 「自動提案を使う」と「自動提案にも資料を使う」は個別にオンにします。自動提案は最大2回/分・最短12秒間隔で、Web検索を自動実行しません。
5. 回答の発話・資料の引用を開いて根拠を確認します。停止、許可解除、資料や接続の変更は生成を中断します。

Conferenceは広い画面では字幕の横に支援を表示し、狭い画面では「資料・AI支援」から開きます。Meetingでは準備画面でも通常のAI回答と資料引用を確認できます。完成した回答と引用は明示保存・Markdown出力に含まれます。Meetingは、完成した回答がある準備画面または会議終了後に「このMacに保存」「Markdownを書き出す」を使えます。発話がなくても回答を保存でき、空セッションや生成途中の回答は保存対象になりません。終了後の振り返り画面にも完成したWeb調査の本文と出典が残ります。

## Webで調べる

両モードの「Webで調べる」、または発話・提案の同名ボタンを開きます。**選択中LLMの接続・モデル・APIキーをそのまま使います。検索サービスの別登録は不要です。** Gemini・OpenAI・Claudeの公式Web検索に接続し、モデル・契約が検索に対応している必要があります。その他の接続はWeb検索未対応と表示します。資料・発話への通常の質問は引き続き利用できます。

調べたいことを入力し、送信先と発話・資料の対象を確認して許可した後、「LLMで調べる」を押します。質問、選択した発話または直近の確定発話、関連資料をLLMへ送ります。**LLMが検索語を作るため、文脈が検索サービスに使われる可能性があります。** 外部検索に使いたくない資料は取り外してください。音声ファイルは送りません。

1操作につきLLMへの要求は1回で、自動再試行はありません。全体60秒で打ち切り、セッションの調査上限は初期20回です。必要なら画面で上限を変更できます。取消した要求も回数に含みます。これは調査操作数で、モデル内部の検索回数や金額の上限ではありません。検索料金や利用制限は選択したLLMサービスに従います。

APIが返した出典を本文のクリック可能な番号とURL一覧で確認できます。表示する時刻は回答を取得した時刻で、記事の公開日ではありません。Geminiが返すGoogle検索候補も表示します。検索実行の証跡や出典がない場合、途中で打ち切られた場合は調査完了として扱いません。

明示保存には回答、発話・資料の引用、WebのURL・タイトル・取得時刻と検索候補表示を含めます。Webページ本文や生の検索レスポンスは保存せず、再閲覧時の自動再検索もしません。実APIでのモデル別品質は未評価です。[検証記録](validation/shared-session-assistance.md)を参照してください。

## Meeting：会議の文字起こしと翻訳

1. ホームの「会議を開く」、またはナビゲーションの「Meeting」を開きます。
2. 会議名と入力別の認識言語（日本語/English）を選びます。開始モードは「文字起こし」が既定です。「リアルタイム翻訳」を選ぶと入力別の翻訳先が現れます。翻訳先の初期候補はマイクが英語、システム音声が日本語で、入力ごとに「翻訳なし」も選べます。参加者への通知・同意を確認します。チェック操作は通知送信を代行しません。
3. 「会議を開始」でモデル準備と入力権限を確認します。選択した入力だけを開始します。システム音声にはMacの他の再生音も含まれます。両方を使う場合は音の重複を避けるためヘッドフォンを推奨します。
4. 「一時停止」で使用中の入力を止め、「再開」で同じ会議の発話を引き継ぎます。準備中は取消できます。停止が失敗した場合は「停止を再試行」を使います。
5. 「会議を終了」は停止と最後の認識結果の取り込みを待って、振り返り画面へ進みます。

翻訳モードでは、原文が認識中の段階から訳文欄を確保し、確定後に届く訳文をその中へ表示します。認識途中と同じ言語の組み合わせは翻訳しません。翻訳はMac内で実行し、APIキーやAI送信許可は不要です。初回には翻訳モデルのダウンロード確認が表示される場合があります。モデル準備や翻訳の失敗時も文字起こしを継続し、「翻訳を再試行」でやり直せます。

開始モードと翻訳先は停止中の準備画面で変更し、次の開始以降の発話に適用します。既存の原文・訳文・翻訳先は保持します。「AIの回答言語」は別設定です。

入力元を「マイク／システム音声」で表示します。入力元は人物を示さず、話者名は自動識別しません。履歴を読んでいる間は自動追従を止め、「最新へ」で復帰します。文字サイズと配色はConferenceと共通です。

「小さく表示」で主画面を隠して小窓へ切り替え、直近3件の原文と訳文を読めます。「展開」で戻れます。小窓の「非表示」や閉じる操作は音声収集を止めません。**ウィンドウメニューの「Meetingの小窓を表示」**で復帰できます。停止には「一時停止」または「会議を終了」を使ってください。画面共有に映らないことは保証しません。

発話と訳文は自動保存しません。会議終了後、「このMacに保存」または「Markdownを書き出す」を選べます。完成した訳文を原文と一緒に保持し、保存済みセッションでも閲覧・再出力できます。停止・終了後も取得済み発話の翻訳は続きます。保存後に訳文が完成した場合は再保存してください。旧版で保存した訳文なしのセッションも読めます。候補の確認・却下にも対応します。「新しい会議」は発話がある場合に破棄確認を表示します。音声は保存せず、AI送信には会議ごとの明示許可が必要です。

### MeetingのAI支援・LLM選択

1. 設定またはMeetingの「LLM設定」を開き、「接続を追加」からGemini / OpenAI / Claude / Kimi / DeepSeek / その他クラウド / ローカルLLMを選びます。
2. 接続名・モデルIDと、ご自身のAPIキーを入力して「保存して選択」を押します。キーは接続ごとにこのMacのKeychainへ保存します。既存Geminiのキーは引き継ぎます。キー・接続先・モデルを変えるとAI送信許可と要約の事前確認が解除されます。
3. 「モデル一覧を取得」で取得した候補から選ぶか、モデルIDを直接入力します。一覧は先頭ページで、すべてのモデルの対応を保証するものではありません。「接続を確認」は架空の短文を1回生成し、接続・応答形式を検証します。クラウドではAPI料金が発生する場合があります。
4. Meetingに表示される送信先と、サービスの料金・データ利用条件を確認して発話・質問の送信を許可します。準備中・会議中・一時停止中に質問を入力して **Ask AI** を押すと、許可前を含む直近の確定発話（最大30件、合計12,000文字）と質問文を送ります。音声は送りません。資料を別途許可した場合は検索した抜粋も送ります。
5. 自動提案は会議ごとに初期オフ。最大2回/分、最短12秒間隔で許可後の発話を使用します。手動質問・自動提案・終了後の要約は同じ接続設定を使用します。決定・アクションを自動確定しません。
6. 主画面・小窓の「AI送信を停止」でAIだけ停止できます。一時停止・会議終了・入力障害でもAI処理が停止します。失敗時の自動再送や、別モデル・別接続への自動切替は行いません。ローカル字幕はAIの障害で停止しません。

**その他クラウド**はOpenAI互換のChat Completions APIに対応します。Base URL（例: `https://example.com/v1`）、モデルID、APIキーを指定します。Kimi・DeepSeekは公式URLとJSONモードのプリセットがあります。カスタムURLを変更すると以前のキーを削除し、再設定を求めます。モデル／サーバーに合わせて応答形式をJSON Schema・JSONモード・プロンプト指定JSONから選べます。不正なJSONはエラーとして扱います。

**ローカルLLM**は、同じMacでOllama / LM Studio等を起動し、導入済みのQwenなどを選びます。Ollamaは通常 `http://localhost:11434/v1`、LM Studioは通常 `http://localhost:1234/v1`。実行ソフト側でAPIサーバーを有効にしてください。APIキーは任意で、空欄なら認証ヘッダーを送りません。モデルのダウンロード・実行エンジンの内蔵は行いません。ローカル接続先がクラウドへ転送する設定かどうかは実行ソフト側で確認してください。LAN上の別PCへのHTTP接続は対象外です。

モデル未起動・未対応の応答形式・認証失敗では接続設定を確認し、手動で再試行してください。通常の質問は30秒、要約は各区間60秒の期限があり、ローカルモデルの読み込みや推論が遅い場合にも適用されます。初期接続は従来のGemini 3.8 Flashです。ChatGPTログイン・サブスク認証は対象外です。

新しい接続の検証範囲は[LLM選択の検証記録](validation/llm-selection.md)を参照してください。

実音声試験は延期中です。実Geminiの評価は、キー登録後に架空の合成会話のみで実施する手順を[検証記録](validation/pr6-insights.md)に記載しています。

AI状態に「会議を一時停止して再開してください」と表示された場合、自動提案は復旧するまでオンにできません。会議を一時停止して再開した後、自動提案をオンにしてください。この間も字幕と手動のAsk AIは利用できます。

実音声を使うZoom/Meet/Teamsの受入試験は延期中です。自動テストと非録音プレビューの結果は[PR5-C検証記録](validation/pr5-c-meeting.md)に記載しています。

## 起動と準備

```sh
xcodebuild -project ConfLingo.xcodeproj -scheme ConfLingo -configuration Debug build
open ~/Library/Developer/Xcode/DerivedData/ConfLingo-*/Build/Products/Debug/ConfLingo.app
```

1. ホームの「字幕を準備する」、または「Conference」を開きます。
2. セッション名、認識する言語、使用する専門用語辞書を選びます。開始モードは「文字起こし」が既定です。翻訳も必要なら「リアルタイム翻訳」を選び、表示される翻訳先を設定します。
3. 認識モデルの準備が完了したら「字幕を開始」を押します。選択した入力に応じて、マイクまたは画面・システムオーディオの使用を許可してください。

起動時や言語変更時に対応状況を確認し、必要な認識モデルを取得します。翻訳モデルの準備でOSのダウンロード確認が表示される場合もあります。会場へ行く前にネットワークのある環境で準備してください。非対応や取得失敗の理由は準備画面に表示され、設定変更や「もう一度確認」で再試行できます。

「認識モデルの準備完了」は、翻訳モデルの取得まで完了したという意味ではありません。必要なモデルを取得した後は、認識・翻訳をMac上で実行します。

新しいセッションやアプリ起動時は「文字起こし」に戻ります。一時停止・再開では選択を維持します。翻訳先の言語は記憶します。

## 字幕を読む

翻訳モードでは、通常幅で原文と翻訳を左右に、狭いウィンドウでは上下に表示します。文字起こし専用モードでは原文だけを表示します。

翻訳モードでは、原文の表示量・文字サイズ・表示幅に応じて訳文の場所を先に確保します。翻訳待ち・失敗・再試行でも場所を保ち、訳文が届いた際の表示のガタつきを抑えます。確保した高さを超える長い訳文は必要な分だけ広げて全文を表示します。この動作はMeetingの通常画面・小窓にも適用されます。

- 「認識中」の原文は途中結果のため、内容が変わることがあります。
- 訳文は確定した発話を文単位でまとめて翻訳します。原文と訳文の行数は一致しない場合があります。
- 「翻訳待ち」「翻訳失敗」は訳文側の状態です。原文を確認できます。
- 過去の字幕へスクロールすると、そのペインの自動追従を止めます。「最新へ」で復帰します。
- 字幕を選択してコピーできます。時刻がある字幕には開始時刻を表示します。

## 操作

| 操作 | 方法 |
|---|---|
| 開始・停止 | 画面下部の「字幕を開始／再開」「停止する」、または⌘R |
| 停止失敗から復帰 | 「停止を再試行」。停止未確認の間は設定移動や消去を行えません |
| 設定変更 | 「字幕の設定」。認識中は停止確認が表示され、停止完了後に移動します |
| 文字サイズ | 上部のA−／A＋、⌘−／⌘＋、または設定画面。10〜48pt |
| 最前面 | 上部の「最前面」、または設定画面 |
| 配色 | 設定→配色でシステム・ライト・ダークを選択 |
| Markdown保存 | 上部の「書き出す」。保存先と名前を選択します |
| 字幕の消去 | 停止後に「字幕を消去」→確認。キャンセルすると内容を保持します |

停止・画面移動では現在の字幕を消去しません。再開すると既存の字幕に追記します。認識中にウィンドウを閉じると停止確認を表示し、開始・停止処理中は閉じる操作を保留します。アプリ終了前には必要な字幕を書き出してください。

## 言語と文字起こし専用モード

言語・辞書・モードは停止中に変更します。認識言語と翻訳先が同じになった場合、翻訳先を自動で切り替えます。対応する組み合わせは実行時の確認結果に従います。

開始モード「文字起こし」では翻訳を行いません。このモードでは「高速確定」も選択できます。高速確定は精度より字幕の速さを優先する設定です。

言語を変更しても既存字幕は残ります。Markdownの言語情報には保存時点の設定を使うため、言語ごとに分けたい場合は変更前に書き出し、字幕を消去してください。

## 専門用語辞書

準備画面または設定画面の「辞書を管理」から編集します。複数の辞書を作成・選択・複製・改名・削除できます。最後の1つは削除できません。

カンマ、読点、改行で用語を区切ります。固定訳語は `evals=評価` のように指定します。訳語を省略した用語は原文表記を保持するよう翻訳時に保護します。「資料の用語を優先」モードでは音声認識にも用語ヒントを渡します。正しい認識・翻訳を保証するものではありません。

```text
ConfLingo
Model Context Protocol
evals=評価
```

変更は自動保存され、次回の開始から適用されます。内容を空にすると用語なしで動作します。辞書はアプリ再起動後も保持されます。

## 保存とデータ

字幕は自動保存されません。「書き出す」は、現在の確定原文と翻訳をMarkdownへ保存します。既定の名前は `<セッション名>-<日時>.md`。未翻訳部分には `(untranslated)` を付け、時刻がある発話には時刻を含めます。認識途中の原文は確定字幕には含まれません。

保存ダイアログのキャンセルや書き込み失敗で字幕を消去しません。字幕の消去は書き出し済みファイルを削除しません。音声ファイルの保存機能はありません。

## 困ったとき

| 症状 | 確認すること |
|---|---|
| 開始できない | 準備画面・エラーバナーを確認。マイク拒否の場合はシステム設定→プライバシーとセキュリティ→マイクを確認 |
| 翻訳が表示されない | 文字起こし専用モードか、翻訳モデルの取得が未完了か、翻訳失敗が表示されているか確認 |
| 認識精度が低い | 入力マイク・周囲の音・登壇者との距離を確認し、固有名詞を辞書へ登録 |
| 停止未確認と表示される | 「停止を再試行」を操作。字幕や入力状態を保持したまま停止を再試行します |

両モードでマイク・外部入力機器、システム音声、両方を選べます。両モードで資料の追加・選択ができ、保存したセッションと資料ライブラリは共通ナビゲーションから開けます。

配布ビルドの作成方法は[README](../README.ja.md#配布)、今回の検証範囲は[PR5-B検証記録](validation/pr5-b-conference.md)を参照してください。

## Meetingでリポジトリを参照する

準備画面または実行中の「資料」→「リポジトリを追加」で、Mac上の作業フォルダを選びます。コード・テスト・文書の一覧を確認し、不要なファイルやフォルダを外して取り込みます。隠しファイル、依存パッケージ、生成物、既知の認証情報ファイルは除外されます。.gitignoreの全規則は適用されず、ソース内の秘密情報の検出も保証しません。

1会議につき1リポジトリ、最大1,000ファイル・500万文字・20 MiB（各1 MiB・10万文字）です。通常のMarkdown/Text資料は従来の20件・合計50万文字です。取り込み・ローカル検索だけでは外部へ送信しません。

- **手動質問:** 発話・質問の送信許可と資料送信許可をオンにすると、検索に一致した最大5箇所・6,000文字と資料名・位置を選択したLLMへ送ります。
- **自動提案:** AI送信と自動提案を有効にし、「自動提案にも資料を使う」をオンにします。初期値はオフで、手動質問や終了後要約とは独立しています。対象の確定発話から最大5箇所・6,000文字を検索して添付します。一致なしは発話のみ、検索失敗は送信せず自動提案を停止します。最大2回/分・最短12秒間隔を維持し、検索と生成の合計30秒で打ち切ります。手動質問が入ると自動処理を中断します。
- **終了後要約:** 「AI要約を準備」の確認画面で「この要約では資料も参照する」を選びます。区間ごとの抜粋、送信量、要求数を確認して開始します。初期値は発話のみで、会議中の資料許可とは別の選択です。
- **根拠の確認:** 会議要約と資料・実装からの補足を分け、引用から相対パス・行番号・内容ハッシュ・取り込み時点の本文を確認できます。Markdownにも補足と引用を含めます。

参照するのは取り込み時点の作業ツリーです。特定のGitコミットや本番稼働状態を示すものではありません。原本が変わっても既存の引用は変わらず、更新する場合は準備中・実行中に取り外して再取り込みします。会議内の資料は会議破棄・アプリ終了で消えますが、明示的にライブラリへ保存した本文は残ります。元ファイルは変更しません。取り外し後も生成済み回答の引用は会議破棄まで残ります。

検索は単語・パス・識別子を使います。資料と共通語のない自然言語質問や、複数ファイルの依存関係の網羅的な理解は保証しません。

## 資料ライブラリ

サイドバーの「資料ライブラリ」→「資料を追加」、またはMeeting／Conferenceの準備中・実行中にMarkdown/Textやリポジトリを取り込み、「ライブラリに保存」を選ぶと、資料本文をこのMacに保持できます。文書は1件ずつ、リポジトリは現在取り込まれているファイルをまとめて保存します。

次の会議では「ライブラリから選択」で保存版を選びます。サイドバーの「資料ライブラリ」では保存名の検索、本文・出典の閲覧、削除ができます。原本を移動・削除しても保存版を利用できます。原本の変更は自動反映されません。

更新する場合は、取り込み直した資料の保存画面から更新先を選び、確認して置き換えてください。同じ資料の再保存は同じ項目を更新します。更新・削除しても、既に会議へ追加した資料や過去の引用は変わりません。会議側も更新するには、旧版を取り外して追加し直します。

保存・閲覧・追加だけでは外部送信しません。AI送信許可は保存されず、ライブラリから会議へ追加した後は手動・自動提案の資料送信を再確認してください。保存済み本文はライブラリから削除するまで残り、会議の破棄では消えません。

最大100項目・保存ファイル合計200 MiBです。会議へ追加できる資料量は既存の上限が適用されます。PDF/OCR・クラウド同期・自動更新は未対応です。

## 会議中に資料を追加する

Meetingは画面内の「資料」、Conferenceは画面上部の「資料・AI支援（件数）」を開きます。「資料を追加」でMarkdown/Textを複数選択でき、「ライブラリから選択」で事前に保存した版を追加できます。リポジトリも実行中に取り込めます。追加のために音声取得を停止する必要はありません。開始・停止処理中は追加できません。

資料追加後はAIへの送信許可を再確認してください。停止・終了した際は未完了の取り込みを中止します。Meeting終了後のReviewでは新規取り込みはできません。Conferenceの停止後は同じセッションとして追加できます。Conferenceの「字幕を消去」は一時資料とAI回答も破棄し、ライブラリの保存版は残します。

## Conferenceで資料に質問する

資料パネルの「資料だけに質問」で接続先と回答言語を確認し、「資料への質問を許可」をオンにして質問します。質問と関連する抜粋だけを送り、字幕や音声は送りません。回答の引用から資料名・行・取り込み時の抜粋を確認できます。中断、資料変更、接続切替で進行中の生成を停止します。

録音前でも、回答が完成すれば資料パネル上部の「このMacに保存」「書き出す」を使えます。回答と引用を保存し、Sessionsから再表示・Markdown出力できます。セッション保存は停止中のみ可能です。空のセッション、用語だけ、生成途中の回答は保存対象になりません。

## 資料から用語を適用する

「資料から専門用語を適用」を開き、「資料から用語を抽出」で見出し・強調語・コード表記・原語/訳語の表から候補を作ります。出典を確認して必要な語にチェックし、必要なら用語・訳語を編集して「選択した用語を適用」を選びます。手入力も可能です。翻訳先言語を確認してください。既存の手入力辞書が優先され、合計100語までです。

適用と「この言語の適用を解除」は、選択した原語言語だけを変更します。Meetingでは日本語と英語を切り替えてそれぞれ適用でき、別言語の用語は保持されます。上限は保持中の全言語と既存辞書を合わせて100語です。資料の取り込みが失敗・取消になった場合は、適用済み用語と編集中の候補を保持します。資料の追加・取り外しが成功した場合は、用語を再確認して適用してください。

Conferenceでは確認した対訳を以降の翻訳に適用します。認識にも用語ヒントを使う場合、開始前に「資料の用語を優先」を選びます。通常の会話認識とは別のDictationTranscriberモデルを使い、必要に応じてモデルをダウンロードします。Conferenceは方式選択時、Meetingは開始時に準備します。実行中の用語更新結果を表示し、失敗時は音声を継続して次回の開始時に適用します。資料変更後は用語候補と適用語を再確認してください。実音声による改善効果は未評価です。

## 資料で原文・訳文を補正する

Conferenceの資料パネルで「字幕と資料を使う補正を許可」をオンにし、確定発話を選びます。参照する抜粋を確認し「資料で補正する」を選ぶと、選択した原文・通常訳・関連抜粋・適用用語をLLMへ送ります。音声は送りません。

候補と元の文を比較して「この補正を採用」を選ぶと、字幕に補正採用と表示します。元の認識結果・訳文は保持し、「採用を解除して元に戻す」で戻せます。生成途中・未採用の候補は保存しません。明示保存とMarkdown出力には完成した資料質問回答と引用、採用した補正、適用用語を含めます。LLMの補正品質は実モデル評価前のため、採用前に内容を確認してください。
