## フォーカス：今回の反復確認は成功

`com.gavrri.conflingo.keyboardreview` の空の合成会議の振り返りを使用。前回と同じ製品dylib。今回は小窓を強制的に前面へ出すAXのRaiseを使わず、Tab/Shift+TabとSpaceで操作した。

| 条件 | 確認 | 結果 |
|---|---|---|
| VoiceOver on・主画面 | Tab 2周18回、Shift+Tab 1周9回 | 27/27、順序通り |
| VoiceOver on・小窓 | Tab 2周6回 | 6/6、順序通り |
| 主画面⇔小窓 | 展開→主画面の「小さく表示」にフォーカス復帰→小窓→Tab | 3/3成功 |
| VoiceOver off・小窓 | Shift+Tab 1周3回 | 3/3、順序通り |
| VoiceOver off・主画面 | Tab 1周9回 | 9/9、順序通り |

合計45回の比較対象のフォーカス移動で停滞・予期しない移動なし。往復3回も成功。切替に使った追加キーは45回に含めない。主画面と小窓の青いフォーカス枠も画面で確認した。

この試験範囲では前回の不安定さは再現せず、製品コードを変更する根拠は得られなかった。過去の失敗を取り消すものではなく、元の同名アプリ複数起動時の原因や、実音声・受信中AI・全画面状態の安定性まで証明するものでもない。主要操作の成功は[前回記録](pr6-keyboard-isolation.md)と合わせて評価する。

## VoiceOver：基本動作を利用者確認済み

前回の操作ツールのアプリ一覧ではVoiceOverが非実行と表示された。今回はOS設定をonにした後、プロセス一覧で **VoiceOver本体、scrod、点字関連サービス** の実行を確認した。アプリ一覧の表示だけでは起動の有無を確定できないため、「VoiceOverが起動しない」とは断定しない。

- VoiceOverユーティリティは取得できた。カーソル表示・キャプション表示は元からon、読み上げ消音はoff、主音声はKyoko（日本語）、音量50％。
- 標準音声プレビューの再生ボタンが停止表示へ変わることを確認。これは実音声が聞こえた証拠ではない。
- OSのシステム設定とConfLingoでControl+Option+Rightを送ったが、読み上げフォーカス・キャプションの変化をツールでは観測できなかった。VoiceOverアプリの取得は `timeoutReached`。
- 直近ログにvoice descriptor検索と音声バッファ関連のエラーがあった。ただし、エラーと未観測の因果関係は確定していない。
- 利用者へ「読み上げが聞こえる／文字パネルだけ見える／どちらも確認できない」の観測を依頼。当初は回答待ちだったが、下記の利用者確認を受領済み。音声を録音して代用せず、AX取得やプレビューの再生表示を実読み上げ合格に代用しない。

## 復元と次の判断

VoiceOverを初期状態のoffへ戻し、設定画面で確認。主音声・音量・キャプション等の設定値は変更していない。OSキーボードナビゲーションはonのまま。検証アプリは主画面の振り返り・両入力停止・AI送信off。

前回67ファイルのソースハッシュが一致。製品未変更なので全体テスト・lintの再実行はせず、今回のUI観測・記録JSON・資料リンク・差分整合を検査。旧API枠11/12、モデル採用枠60/60を維持する。

利用者による実音声/キャプションの観測と設定ボタンの実キー操作を、下記の通り受領した。今回の基本確認は利用者確認として完了し、追加の同じ質問は不要。実音声等を含むPR6/Gate U全体の完了とは区別する。

## 利用者による最終確認

1. 読み上げ音声と文字パネルについて、ユーザーが「聞こえた、見えた」と回答。実読み上げ・キャプション表示を利用者確認済みへ更新。
2. ツールからControl+Option+Spaceを送った回は画面遷移を確認できなかったため、設定にフォーカスを置き、利用者へ実キー操作を依頼。ユーザーは「設定画面が開いた」と回答。VoiceOverの基本ボタン操作を利用者確認として記録。
3. 回答後のツール取得は振り返り画面・設定ボタンのフォーカスのままで、画面遷移は独立に追認できなかった。利用者の申告とツール観測を同一の証拠とは扱わず、対象ウィンドウ/取得状態の不一致原因は未確定とする。
4. VoiceOverは設定画面でon→offの復元を確認。製品変更・追加API送信なし。

確認範囲は読み上げ・キャプション・設定ボタンの代表的な基本操作。全画面の読み順や会議の全操作をVoiceOverのみで網羅したものではない。
