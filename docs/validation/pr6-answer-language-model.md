## 実装した設定

- 設定画面とMeetingのAI欄に「AIの回答言語」を追加。日本語/Englishを選択し、初期値は日本語。
- `aiAnswerLanguage`をUserDefaultsへ保存。字幕の認識言語・翻訳先とは独立する。プレビューは専用の保存先、テストは注入した一時保存先を使用。
- 手動質問・自動提案とも要求作成時の選択を`InsightRequest.answerLanguage`へ固定し、最終入力JSONへ明示。送信中の変更は次の要求から反映する。
- プロンプトの「質問言語を使う」という契約を、利用者が選んだ言語を優先する契約へ置き換えた。質問本文は書き換えない。
- 出力の自動翻訳・再試行・主張別スキーマ・独自の意味検証器は追加していない。

### 失敗の内訳

番号は送信順で1始まり。[全件のメタデータ・判定JSON](pr6-answer-language-model-2026-11-10.json)を参照。

| 番号 | 条件・ケース | 不合格理由 |
|---|---|---|
| 1 | minimal / long-en-question | 根拠にないレビュー未完了と開始可否の因果を付加 |
| 6、41 | minimal / mixed-en-feasibility（2回とも） | レビュー進行中を可否不明の理由として断定 |
| 24 | minimal / subject-explicit | 明示されたワークショップの日程変更を、予定訂正か実曜日か不明と付け加えて曖昧扱い |
| 39 | minimal / long-en-question | 30.03秒で接続timeout。再送なし、使用量不明 |
| 4 | high / mixed-en-feasibility | 進捗・更新見込みを可否不明へ因果で結んだ |
| 37 | high / long-en-question | 質問した開始可否の不明点と確認提案を省略し、進捗・更新見込みだけを回答 |

3.8 Flashは、これらのケースで要求された情報を保持しつつ、根拠にない因果を補わなかった。依存が明示された対照ではその関係を保持し、見込み/予定、期限/特定日、対象不明/明示も区別した。単に短く無難な回答にして合格したわけではない。

前の評価で要確認とした一般語eventについては、今回の計画で「単独では不合格にしない。具体的な対象や未提示の予定成立を補えば不合格」と事前固定した。過去の判定を変更していない。
