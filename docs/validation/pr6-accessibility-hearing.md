- 製品内に `keyDown` / `onKeyPress` / `FocusState` / `makeFirstResponder` 等によるTab独自処理・強制フォーカスは検出しなかった。原因の否定を保証するものではない。
- `ContentView` の非表示Meetingには `disabled` と `accessibilityHidden` があり、今回の表示中Meetingではそれらは解除される。
- 小窓は非アクティブ化パネルだが、今回の停滞は通常の主画面でも再現したため、小窓設定だけを原因とはできない。
- 過去の `pr6-nonrecording-ui-acceptance.md` には再選択後にTab経路が成立した記録があり、常に失敗する製品不具合とは断定できない。
- 前回の67ファイルのハッシュ一致。追加API要求0、製品変更0、OS設定変更0。
