## VoiceOverと操作ツールの制約

- システム設定→アクセシビリティ→VoiceOverで、開始時の状態が**オフ**であることを確認。
- 有効化操作は自動承認レビューが拒否。「OS全体の設定変更と音声出力に明示的な承認がない」という理由。別のショートカットや実行手段で回避していない。
- その後、ユーザー「OK」で一時有効化・終了後のオフ復元を承認。設定画面でオンを確認し、ユーザーから「音声も文字パネルも確認できる」と回答を受領。起動直後の出力に関する報告として保持するが、対象画面の読み上げ・操作合格には数えない。
- ユーティリティでVoiceOverカーソル表示・キャプションパネル表示が元からオンであることを確認し、変更していない。
- ツールからControl+Option+Rightを送ってもアプリのフォーカスや画面の変化を観測できない。通常Tabで「保存」へフォーカスを置き、ユーザーへ実キーのControl+Option+Spaceによる実行を依頼。その後、ユーザーから「どちらも確認不可。ボイスオーバーは一旦停止」と回答を受領。「保存」の読み上げ・一覧への遷移は確認不可として記録し、VoiceOverの受入を保留した。
- 停止依頼後、システム設定のVoiceOverをオフに戻し、`AX_VOICEOVER_ENABLED: off`を確認。以後の有効化・操作試行は行っていない。
- AXラベル・通常Tabの成功はVoiceOver成功に置き換えない。過去のVoiceOver基本操作の利用者確認も、この3画面の全経路受入へ流用しない。
- MarkdownボタンのSpace操作も一度拒否されたが、`SavedSessionView.exportMarkdown()`がNSSavePanelを開き、OKを選ぶまで書き込まないことをソースで確認・提示した。同じ操作の再試行は許可され、パネル表示→Escape取消を確認できた。この操作の承認待ちは解消済み。
