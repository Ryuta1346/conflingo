## 実装

- ローカルフォルダを選び、コード・テスト・文書を対象一覧で選択。ディレクトリ単位の除外、上限、取消、除外理由を表示する。
- 隠しファイル・生成物・依存パッケージ・既知の認証情報・リンク・入れ子リポジトリを除外。読み込みはディレクトリFDに対する`openat`と`O_NOFOLLOW`で行い、確認後の置換とファイル更新を検出する。Gitコマンドやコード実行はしない。
- 会議内だけの不変スナップショットを索引化。同本文の別パスも別出典とし、相対パス・行・内容ハッシュ・snapshot IDを保持。パス・識別子分割をFTS5検索へ加える。
- 手動質問は従来の許可と最大5箇所・6,000文字を維持。自動提案への資料付加は行わない。
- 終了後要約では初期オフの独立した資料参照選択を追加。全発話を区間ごとにローカル検索し、送信前に抜粋・量・要求数を確認する。
- 会議要約と資料補足を構造化フィールドで分け、発話根拠と資料引用を検証。資料変更・停止・破棄・キー変更で待機/処理中の要約を無効化し、旧完成版を保持する。
- ReviewとMarkdownに補足と引用を表示する。既存の発話のみ要約と通常資料は維持する。

## ネイティブUIで確認したこと

別bundle IDのDebugコピーで `--meeting-preview` を使用。`--meeting-live-ai`は指定せず、fake入力・fake AI・fakeキー保存を使用した。利用者の実リポジトリは読まず、作成した小さな合成fixtureだけを取り込んだ。

1. 初版では「リポジトリを追加」を押してもパネルが表示されず、既存の「資料を追加」は表示された。フォルダ選択と対象確認シートの表示経路を分け、フォルダ選択は`NSOpenPanel`に変更。修正版で表示成功。
2. `/private/tmp/conflingo-repository-ui-fixture`をOSパネルから選択し、README・Swiftソース・Swiftテストの3件と、`.env`・`node_modules`の除外理由を確認。Testsフォルダを外すと2件になり、戻して3件を取り込めた。
3. `reviewStatus`で検索し、ソースが先頭に出ること、引用から相対パス・1–2行・内容ハッシュと原文を開けることを確認。
4. fake Meetingの手動質問から資料3箇所を参照し、コード引用へ遷移。固定の架空回答であり、回答の意味的品質の検証ではない。
5. `repository-review`専用プレビューで合成12発話と2資料を準備。要約の資料参照は初期オフ。オンにすると1区間・最大1要求、2抜粋・131文字、コードと文書の位置・本文が確認できた。
6. 確認画面で取消→再度開くと参照はオフ。改めてオンにしてfake生成し、「会議の要約」「資料・実装からの補足」と各根拠を別表示した。要約の引用から元のコードを開けた。
7. OS保存パネルでMarkdownを書き出し、保存完了表示とファイルの内容を確認。[書き出した合成サンプル](fixtures/repository-summary-ui-2026-11-11.md)には補足、相対パス、行、版、抜粋を含む。
8. 約743×558ptの狭幅でスクロールして補足・引用に到達できることを確認。確認画面でSpaceによる資料選択とEscapeによる取消を確認し、前回の完成版が保持された。

## 制限と残る検証

- 実APIを使った資料付き要約の意味的品質、自然言語からコードを探す実用精度、実音声との結合は未検証。既存PR6/7/8の合成実API結果を、新しいプロンプト・検索・要約契約の合格へ流用しない。
- 自動テストとネイティブUIは小さな合成リポジトリ。1,000ファイル級の実リポジトリでの操作性・索引化時間・メモリは未実測。全言語の構文理解・依存関係探索、意味検索、完全な.gitignore評価は初版の範囲外。
- 新規画面のVoiceOver全経路、配布署名のファイル権限、OSの実際の権限拒否→復旧は未確認。全UI/Gate U完了とは扱わない。
- 単独で境界・取消・契約・差分を確認。独立レビューは未実施。
- 既存品質Gateと受入完了数2/12は維持。今回の実装承認は実API評価予算や実リポジトリの外部送信許可ではない。
