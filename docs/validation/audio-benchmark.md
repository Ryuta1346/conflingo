# 音声素材・実機試験・計測手順

更新: 2026-11-08。以下は再現用の手順であり、実機で合格した記録ではない。

## 素材の出所と同意

- [英語原稿](fixtures/conference-en.txt)・[日本語原稿](fixtures/conference-ja.txt)は本タスクで新規作成した架空の会議。個人情報・実会議の引用を含まない。
- 第三者の会議音声や動画は使わない。手元で原稿を読み上げるか、macOSのインストール済み音声でローカル検証用の音声を生成する。
- 合成音声はリポジトリへ追加・配布しない。原稿、音声名、話速、OS、ファイルのSHA-256を記録し、各実行では同じファイルを再利用する。
- マイク試験では周囲の会話も入力され得る。実施前に場所・入力範囲・同席者の了解を確認する。試験のための室内録音・画面録画・クラウド送信は既定で行わない。
- 素材、Markdown出力、計測結果は試験専用フォルダへ保存する。保持期間と削除対象を決め、個人の既存辞書や保存物を消さない。

## 合成音声の準備

```sh
# インストール済みの音声名を確認。未インストール音声はここでは追加しない。
say -v '?'
mkdir -p /private/tmp/conflingo-benchmark
# 下記はSamantha / Kyokoが利用可能な場合の例。
say -v Samantha -r 150 -f docs/validation/fixtures/conference-en.txt -o /private/tmp/conflingo-benchmark/conference-en.aiff
say -v Kyoko -r 150 -f docs/validation/fixtures/conference-ja.txt -o /private/tmp/conflingo-benchmark/conference-ja.aiff
shasum -a 256 /private/tmp/conflingo-benchmark/*.aiff
```

声名が異なる場合はインストール済みの英語・日本語音声に置き換え、使用した名前を記録する。速度・抑揚・音質に依存するため合成音声のみで実会議精度を判断しない。

### 2026-11-08の素材準備結果

macOS 26.5.2、上記コマンドで生成。`afinfo`で音声データが存在することを確認した。sandbox内では終了コード0でも0秒のファイルになったため、そのファイルを採用せず、制限外で再生成した。

## 権限と試験準備

### 実機音声試験の実施方針

2026-11-08、ユーザーの「後回しで良い」という回答により、実機音声試験は後日実施とする。現在は回答待ちではない。マイク入力・スピーカー再生は実施しておらず、実音声・実翻訳の回帰は未検証のまま残す。

再開時には周囲の了解と実施可能な場所を確認し、本書のケースに沿って試験する。OSのマイク権限ダイアログが出た場合はその時点で許可を確認する。

音声はオンデバイス処理。外部AIへの送信はなく、試験のための室内音声録音ファイルは作成しない。

1. ビルド済みアプリを起動し、OS/Xcode/アプリのリビジョン、マイク、出力先、音量、辞書・言語設定を記録する。
2. モデル準備画面の結果を確認する。モデルの追加ダウンロードが必要な場合は利用者が確認して実行する。
3. マイク許可の状態を記録する。初回ダイアログ・拒否の試験は専用macOSユーザーで行うか、利用者が設定変更を了承した環境で行う。`tccutil reset`で既存アプリの許可を一括初期化しない。
4. 文字起こし専用から開始し、英語・日本語の順に試す。英→日の翻訳は別試行にする。
5. 専用の辞書プロファイルを新規作成し、`API=エーピーアイ`を登録する。試験後は元のプロファイル選択へ戻す。

| ID | 操作 | 観測点 |

| C02 | マイク許可後、Start→原稿の読み上げ→Stop | 途中/確定字幕、停止後に入力が継続しないこと |

| C04 | 文の途中でStop→再開→別の文→Stop | 保留文の一度だけの確定、重複・前回入力の混入なし |
| C05 | 文字起こし専用→英日翻訳 | 表示・出力の切替、モデル未準備時の案内 |
| C06 | 辞書作成/複製/切替/名前変更/削除→再起動 | 内容と選択の保持、既存プロファイルの保持 |
| C07 | Save Markdown→内容確認、保存キャンセル | 原文・訳文・時刻、専用モードでは訳文なし |
| C08 | Cmd+R、Cmd+−/Cmd+＋、最前面、Clear | [回帰表](conference-baseline.md)に沿った操作と表示 |
| C09 | マイク拒否状態でStart（専用環境） | idleへ戻る、理由を表示、無断入力なし |

入力と出力が同じ機器へループしない構成を使う。C10は周囲の了解を得てから `afplay /private/tmp/conflingo-benchmark/conference-en.aiff` で再生する。ヘッドフォンではマイクへの入力条件が変わるため同じ試験として比較しない。

## 計測基盤（PR0: 外部観測）

PR0では既存コードに計測用のログや会議本文の記録を追加しない。CPU/メモリはOSから取得し、遅延は下記の手動観測として記録する。PR4以降の共通時計による自動計測とは区別する。

### CPU・メモリ

対象アプリのPIDをアクティビティモニタで確認し、次を実行する。PIDが自分の試験アプリであることを確認する。

```sh
app_pid=12345 # 実際のPIDに置き換える
mkdir -p /private/tmp/conflingo-benchmark
metrics_path=$(mktemp /private/tmp/conflingo-benchmark/metrics.XXXXXX)
printf 'timestamp_utc,cpu_percent,rss_kib\n' > "$metrics_path"
for sample_index in $(seq 1 60); do
  values=$(ps -p "$app_pid" -o %cpu=,rss=)
  [ -n "$values" ] || break
  printf '%s,%s\n' "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$(echo "$values" | awk '{print $1 "," $2}')" >> "$metrics_path"
  sleep 1
done
echo "$metrics_path"
```

アイドル・文字起こし・翻訳を別ファイルで記録する。RSSはKiB、CPUはpsの測定値で複数コア使用時は100%を超え得る。psの実行時間があるため厳密な1秒間隔ではない。時刻列を使って比較し、PID終了後の行を作らない。

### 遅延・認識品質

- 同じ素材・デバイス・設定で少なくとも3回実施し、試行番号を付ける。
- 発話開始、発話終了、最初のpartial表示、final確定、訳文表示を同じストップウォッチで観測する。
- `partial遅延 = 最初のpartial − 発話開始`、`final遅延 = final確定 − 発話終了`、`訳文遅延 = 訳文表示 − 発話終了` とする。
- 手動観測の反応誤差を含む参考値であり、p95等の性能保証には使わない。得られない値を0で埋めない。
- 原稿と確定字幕を比較し、欠落・置換・重複、APIと数値の認識を記録する。PR0では精度の合格閾値を捏造しない。
