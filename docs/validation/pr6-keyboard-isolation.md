## 比較条件

- 元のbundle ID `com.gavrri.conflingo` で3プロセスが同時起動していた。ユーザー回答後に取得した画面は、直前の振り返りからホームへ変化しており、対象・状態の連続性に注意が必要。
- OSキーボードナビゲーションはon。off→onで再適用し、最終onへ復元。システム設定ではTabによる検索欄→戻るボタンの移動を確認。
- 認証済みホストを `/private/tmp/conflingo-keyboard-review/ConfLingoKeyboardReview.app` へコピーし、bundle IDを `com.gavrri.conflingo.keyboardreview` に変更してローカル署名。`--meeting-preview --meeting-state=setup` で起動。`--meeting-live-ai` は指定せず、fake音声・fake AIクライアント・fakeキーストアを使用。
- 元ホストのCDHashは `5c9b006725a3c6d50b85220dbaec7c4ea76c85d9` のまま。元ソース67ファイルのハッシュが前回と一致し、コピーの `ConfLingo.debug.dylib` も元と同一。変更したのは検証コピーの識別子等と署名のみ。
- 設定の再適用と識別子の分離を両方行っているため、改善原因を識別子の分離だけには帰属しない。検証コピーの成功を、元ホストの全操作合格に読み替えない。

## キーボードで確認した経路

| 経路 | 操作と結果 |
|---|---|
| 主画面の移動 | Tabで字幕拡大→最前面→ホーム→Conference→Meeting→設定。フォーカスをAXでも確認 |
| 設定とMeetingの往復 | Spaceで設定表示、Shift+TabでMeetingへ戻りSpaceで表示 |
| 会議準備 | 会議名→入力言語2つ→同意→API設定の順にTabで到達。同意はSpaceでonにし、開始が有効になった |
| API設定シート | Spaceで開き、Escapeで閉じる。元のAPI設定ボタンへフォーカス復帰。キーの入力・保存なし |
| 回答言語 | Tabで到達し、Space→Down→EnterでEnglish。後でSpace→Up→Enterで日本語へ復元 |
| 開始 | Tabで会議開始へ到達、Spaceでlive状態に遷移 |
| 主画面の一時停止・再開 | Tabで各ボタンへ到達しSpace。fake入力の停止→取得中を確認 |
| 小窓 | 「小さく表示」をSpaceで実行。小窓は最初のTabでフォーカスを観測できず、CUAのRaise後に移動を確認 |
| 小窓の一時停止・再開 | Tab→Spaceで停止・取得中を確認 |
| 展開 | Tabで展開へ到達しSpace。主画面に復帰 |
| 小窓の会議終了 | Tabで会議を終了へ到達、Spaceで「会議を終了しました」・両入力停止へ遷移 |
| 終了後の小窓非表示 | Tabで非表示へ到達しSpace。小窓が消え、取得対象は主画面の振り返りになった |

小窓の再表示を試した一回と、Shift+Tabを試した一回は期待したフォーカス遷移にならず、その回を成功には数えなかった。状態を取得し直し、上表の成功を別途確認した。小窓のRaiseはAX操作であり、全行程を物理キーボードだけで確認したものではない。空の合成会議なので、根拠リンクやAI受信中の停止をこの試験で再評価していない。

## VoiceOver

OS設定でoff→onは確認できたが、アプリ一覧ではVoiceOver非実行、Control+Option+Right後も読み上げフォーカス・キャプション変化を観測できなかった。起動取得の長いタイムアウトは繰り返さず、offに戻した。AXラベルが読めることやTab移動成功をVoiceOver合格には代用しない。

次はVoiceOverが実際に起動・読み上げできる環境で確認する。OS側でも読み上げが始まらない状況では製品の読み上げ不具合とは断定できない。フォーカスの一時的な停滞も、単一プロセス・通常のキー入力で安定して再現できた場合に修正対象を定める。
